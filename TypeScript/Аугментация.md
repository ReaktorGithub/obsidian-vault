**Аугментация (Declaration Merging) в TypeScript** — это механизм, который позволяет расширять существующие типы, интерфейсы и пространства имён, добавляя к ним новые свойства или методы без изменения исходного объявления.

Чаще всего аугментацию используют, чтобы расширить типы сторонних библиотек или добавить собственные свойства в объекты, например `Request` в Express.

### 1. Аугментация интерфейсов

TypeScript автоматически объединяет интерфейсы с одинаковыми именами.

```
interface User {
  name: string;
}

interface User {
  age: number;
}

const user: User = {
  name: "Oleg",
  age: 30,
};
```

В результате TypeScript воспринимает `User` так:

```
interface User {
  name: string;
  age: number;
}
```

Это называется **слиянием объявлений (Declaration Merging)**.

### 2. Аугментация типов сторонних библиотек

Представим, что мы используем Express и хотим добавить в объект `Request` свойство `user`.

```
// types/express.d.ts

declare global {
  namespace Express {
    interface Request {
      user?: {
        id: string;
        email: string;
      };
    }
  }
}

export {};
```

Теперь TypeScript будет знать о свойстве `user` в Express:

```
app.get("/profile", (req, res) => {
  console.log(req.user?.id);
  res.send("Profile");
});
```

Без аугментации TypeScript не знал бы о нашем свойстве и выдавал бы ошибку.

**Важно:** аугментация изменяет только информацию о типах во время компиляции. Она не добавляет свойство `user` в объект во время выполнения. Реальное значение должен установить, например, middleware аутентификации.

### 3. Аугментация модулей

Можно расширить типы конкретного модуля с помощью `declare module`.

Допустим, нужно добавить свойство `customProperty` в тип из сторонней библиотеки:

```
// my-library.d.ts

import "some-library";

declare module "some-library" {
  interface SomeInterface {
    customProperty: string;
  }
}
```

Теперь интерфейс `SomeInterface` будет включать новое свойство.

Обрати внимание: здесь предполагается, что библиотека экспортирует интерфейс `SomeInterface`, а не тип, который нельзя объединить таким способом.

### 4. Где применяется аугментация?

- **Express** — добавление свойств `user`, `session` и других в объект `Request`.
- **Библиотеки** — расширение существующих типов без изменения исходного кода.
- **Глобальные типы** — добавление собственных свойств в глобальные интерфейсы, например `Window`.
- **React** — расширение типов сторонних библиотек или глобальных объектов, используемых приложением.

### Что важно запомнить для собеседования

|Понятие|Значение|
|---|---|
|Declaration Merging|Объединение нескольких объявлений с одинаковым именем|
|Module Augmentation|Расширение типов существующего модуля|
|`declare global`|Расширение глобальных типов и интерфейсов|
|`declare module`|Объявление или расширение типов модуля в зависимости от контекста|
|Runtime|Аугментация не меняет реальный JavaScript-код|

**Короткий ответ для собеседования:**

Аугментация в TypeScript позволяет расширять существующие типы, интерфейсы и модули без изменения их исходного кода. Например, можно добавить свойство `user` в интерфейс `Request` из Express, чтобы TypeScript учитывал его после прохождения middleware аутентификации. При этом аугментация влияет только на систему типов и не изменяет поведение приложения во время выполнения.
