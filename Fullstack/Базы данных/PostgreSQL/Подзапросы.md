**Подзапрос (subquery)** — SQL-запрос, вложенный в другой запрос. Его результат используется основным запросом для фильтрации, вычислений или получения данных.

Подзапросы можно использовать в `SELECT`, `FROM`, `WHERE`, `HAVING` и других частях SQL-запроса.

Для примеров возьмём таблицы `users` и `orders`.

**Таблица `users`**

|id|name|city|
|---|---|---|
|1|Олег|Москва|
|2|Анна|Тула|
|3|Иван|Москва|

**Таблица `orders`**

|id|user_id|amount|
|---|---|---|
|101|1|1000|
|102|1|3000|
|103|2|500|

## Обычный подзапрос

Подзапрос выполняется внутри основного запроса и возвращает значение или набор значений, которые использует внешний запрос.

Например, найдём заказы, сумма которых выше средней суммы всех заказов:

```
SELECT *
FROM orders
WHERE amount > (
    SELECT AVG(amount)
    FROM orders
);
```

Внутренний запрос вычисляет среднюю сумму: `1500`.

Внешний запрос возвращает заказы на сумму больше 1500.

Результат:

|id|user_id|amount|
|---|---|---|
|102|1|3000|

## Скалярный подзапрос

**Скалярный подзапрос** возвращает одно значение: одну строку и один столбец.

Его можно использовать там, где ожидается одно значение.

```
SELECT
    name,
    (SELECT AVG(amount) FROM orders) AS average_order
FROM users;
```

Результат:

|name|average_order|
|---|---|
|Олег|1500|
|Анна|1500|
|Иван|1500|

Подзапрос вычисляет среднюю сумму заказа, которая выводится для каждого пользователя.

Если скалярный подзапрос возвращает несколько строк, PostgreSQL выдаёт ошибку. Если он возвращает ноль строк, результатом будет `NULL`.

## Подзапрос в WHERE

Подзапрос позволяет фильтровать записи по результатам другого запроса.

Например, найдём пользователей, у которых есть заказы на сумму больше 2000:

```
SELECT *
FROM users
WHERE id IN (
    SELECT user_id
    FROM orders
    WHERE amount > 2000
);
```

Внутренний запрос возвращает `user_id` пользователей с подходящими заказами.

Внешний запрос выбирает этих пользователей.

Результат:

|id|name|city|
|---|---|---|
|1|Олег|Москва|

## Подзапрос в FROM

Подзапрос в `FROM` создаёт временный набор данных, с которым работает внешний запрос. Такой подзапрос называют производной таблицей (derived table).

Например, посчитаем общую сумму заказов каждого пользователя, а затем выберем тех, у кого она больше 1000:

```
SELECT *
FROM (
    SELECT user_id, SUM(amount) AS total
    FROM orders
    GROUP BY user_id
) AS user_totals
WHERE total > 1000;
```

Результат:

|user_id|total|
|---|---|
|1|4000|

**Важно:** подзапросу в `FROM` необходимо назначить псевдоним, например `user_totals`.

## Подзапрос в SELECT

Подзапрос может вычислять отдельное значение для каждой строки внешнего запроса.

Например, посчитаем количество заказов каждого пользователя:

```
SELECT
    u.name,
    (
        SELECT COUNT(*)
        FROM orders o
        WHERE o.user_id = u.id
    ) AS orders_count
FROM users u;
```

Результат:

|name|orders_count|
|---|---|
|Олег|2|
|Анна|1|
|Иван|0|

Здесь внутренний запрос обращается к `u.id` из внешнего запроса. Это **коррелированный подзапрос**.

## Коррелированный подзапрос

**Коррелированный подзапрос** — подзапрос, который использует значения из внешнего запроса.

Пример:

```
SELECT *
FROM users u
WHERE EXISTS (
    SELECT 1
    FROM orders o
    WHERE o.user_id = u.id
);
```

Для каждого пользователя проверяется, существует ли хотя бы один связанный заказ.

Результат:

|id|name|city|
|---|---|---|
|1|Олег|Москва|
|2|Анна|Тула|

Коррелированный подзапрос логически зависит от текущей строки внешнего запроса. PostgreSQL может оптимизировать его выполнение, поэтому не обязательно буквально выполнять подзапрос отдельно для каждой строки.

# EXISTS и NOT EXISTS

## EXISTS

`EXISTS` проверяет, возвращает ли подзапрос хотя бы одну строку.

- Возвращает `TRUE`, если найдена хотя бы одна строка.
- Возвращает `FALSE`, если строк нет.

Пример:

```
SELECT *
FROM users u
WHERE EXISTS (
    SELECT 1
    FROM orders o
    WHERE o.user_id = u.id
);
```

Возвращает пользователей, у которых есть хотя бы один заказ.

**Почему `SELECT 1`?**

Потому что `EXISTS` проверяет наличие строк, а не значения в них. Можно было бы написать `SELECT *`, но `SELECT 1` явно показывает, что сами данные не нужны.

## NOT EXISTS

`NOT EXISTS` проверяет, что подзапрос не возвращает ни одной строки.

Например, найдём пользователей без заказов:

```
SELECT *
FROM users u
WHERE NOT EXISTS (
    SELECT 1
    FROM orders o
    WHERE o.user_id = u.id
);
```

Результат:

|id|name|city|
|---|---|---|
|3|Иван|Москва|

**Типичная задача:** найти записи одной таблицы, для которых нет соответствующих записей в другой.

---

# IN и NOT IN

## IN

`IN` проверяет, входит ли значение в заданный набор значений.

```
SELECT *
FROM users
WHERE id IN (1, 3);
```

Можно использовать подзапрос:

```
SELECT *
FROM users
WHERE id IN (
    SELECT user_id
    FROM orders
);
```

Возвращает пользователей, чьи идентификаторы встречаются среди `user_id` заказов.

По смыслу это близко к `EXISTS`, но `IN` сравнивает значение с набором значений, а `EXISTS` проверяет наличие подходящих строк.

## NOT IN

`NOT IN` проверяет, что значение не входит в набор.

```
SELECT *
FROM users
WHERE id NOT IN (
    SELECT user_id
    FROM orders
);
```

В нашем примере запрос найдёт Ивана.

**Важный нюанс с NULL:** если подзапрос возвращает хотя бы один `NULL`, условие `NOT IN` может стать `UNKNOWN` и не вернуть ожидаемые строки.

Например:

```
SELECT 3 NOT IN (1, NULL);
```

Результат — `NULL`, а не `TRUE`.

Поэтому для поиска записей, которым не соответствует другая запись, часто безопаснее использовать `NOT EXISTS`.

# ANY и SOME

`ANY` проверяет, выполняется ли условие хотя бы для одного значения, возвращённого подзапросом.

`SOME` — синоним `ANY` в PostgreSQL.

Допустим, нужно найти заказы, сумма которых больше хотя бы одного заказа пользователя с `id = 1`:

```
SELECT *
FROM orders
WHERE amount > ANY (
    SELECT amount
    FROM orders
    WHERE user_id = 1
);
```

Заказы пользователя 1 имеют суммы 1000 и 3000.

Условие `amount > ANY (...)` означает, что сумма должна быть больше хотя бы одного из этих значений. В данном случае достаточно превысить 1000.

Результат:

|id|user_id|amount|
|---|---|---|
|102|1|3000|

### Примеры логики ANY

Пусть подзапрос возвращает значения `10, 20, 30`.

|Условие|Результат|Объяснение|
|---|---|---|
|`5 > ANY (...)`|`FALSE`|5 не больше ни одного значения|
|`15 > ANY (...)`|`TRUE`|15 больше 10|
|`35 > ANY (...)`|`TRUE`|35 больше всех значений|

Для сравнения с `ANY` часто используются операторы `=`, `<>`, `<`, `>`, `<=`, `>=`.

Например:

```
WHERE age = ANY (SELECT age FROM users)
```

По смыслу эквивалентно `age IN (SELECT age FROM users)`.

---

# ALL

`ALL` проверяет, выполняется ли условие для **каждого значения**, возвращённого подзапросом.

Например, найдём заказы, сумма которых больше всех заказов пользователя с `id = 1`:

```
SELECT *
FROM orders
WHERE amount > ALL (
    SELECT amount
    FROM orders
    WHERE user_id = 1
);
```

Заказы пользователя 1 имеют суммы 1000 и 3000.

Условие требует, чтобы сумма была больше и 1000, и 3000, то есть больше 3000.

В текущих данных таких заказов нет, поэтому результат пустой.

### ANY и ALL: разница

Пусть подзапрос возвращает значения `10, 20, 30`.

|Условие|Результат|Объяснение|
|---|---|---|
|`25 > ANY (...)`|`TRUE`|25 больше хотя бы одного значения|
|`25 > ALL (...)`|`FALSE`|25 не больше всех значений|
|`35 > ANY (...)`|`TRUE`|35 больше хотя бы одного значения|
|`35 > ALL (...)`|`TRUE`|35 больше каждого значения|

**Важно:** если подзапрос возвращает пустой набор, `ANY` возвращает `FALSE`, а `ALL` — `TRUE`. Если сравнение с элементами набора содержит `NULL`, результат может быть `NULL`, когда нельзя однозначно определить истинность условия.

---

# Сравнение подзапросов с агрегатными функциями

Иногда вместо `ANY` и `ALL` удобнее использовать агрегатные функции.

Например, условие:

```
WHERE amount > ALL (
    SELECT amount
    FROM orders
    WHERE user_id = 1
)
```

При непустом наборе значений без `NULL` можно выразить через `MAX()`:

```
WHERE amount > (
    SELECT MAX(amount)
    FROM orders
    WHERE user_id = 1
)
```

А условие:

```
WHERE amount > ANY (
    SELECT amount
    FROM orders
    WHERE user_id = 1
)
```

Для непустого набора без `NULL` можно выразить через `MIN()`:

```
WHERE amount > (
    SELECT MIN(amount)
    FROM orders
    WHERE user_id = 1
)
```

Однако эти варианты не полностью эквивалентны во всех случаях: при пустом наборе, наличии `NULL` или использовании других операторов сравнения поведение может различаться.

---

# Подзапросы с агрегатными функциями

Подзапросы часто используются с `COUNT`, `SUM`, `AVG`, `MIN` и `MAX`.

Например, найдём пользователей, у которых сумма заказов больше 2000:

```
SELECT *
FROM users u
WHERE (
    SELECT COALESCE(SUM(o.amount), 0)
    FROM orders o
    WHERE o.user_id = u.id
) > 2000;
```

`SUM()` считает сумму заказов пользователя, а `COALESCE()` заменяет `NULL` на 0, если заказов нет.

В этом примере будет выбран Олег с суммой заказов 4000.

---

# Подзапросы с HAVING

Подзапросы можно использовать для фильтрации групп.

Например, найдём пользователей, у которых больше одного заказа:

```
SELECT user_id, COUNT(*) AS orders_count
FROM orders
GROUP BY user_id
HAVING COUNT(*) > 1;
```

Результат:

|user_id|orders_count|
|---|---|
|1|2|

А вот пример с подзапросом: найдём пользователей, у которых сумма заказов выше средней суммы заказов на пользователя.

```
SELECT user_id, SUM(amount) AS total
FROM orders
GROUP BY user_id
HAVING SUM(amount) > (
    SELECT AVG(user_total)
    FROM (
        SELECT SUM(amount) AS user_total
        FROM orders
        GROUP BY user_id
    ) AS totals
);
```

Внутренний запрос считает сумму заказов каждого пользователя. Следующий уровень вычисляет среднюю сумму по пользователям, а внешний запрос выбирает группы, превышающие это значение.

# Подзапросы и JOIN

Некоторые задачи можно решить как подзапросами, так и через `JOIN`.

Например, получить пользователей, у которых есть заказы.

Через `EXISTS`:

```
SELECT *
FROM users u
WHERE EXISTS (
    SELECT 1
    FROM orders o
    WHERE o.user_id = u.id
);
```

Через `INNER JOIN`:

```
SELECT DISTINCT u.*
FROM users u
INNER JOIN orders o ON o.user_id = u.id;
```

Оба запроса возвращают пользователей с заказами.

Но есть различия:

- `EXISTS` проверяет наличие связанной записи и не размножает строки пользователя при нескольких заказах.
- `JOIN` объединяет строки таблиц и может возвращать пользователя несколько раз, если у него несколько заказов. В примере `DISTINCT` убирает повторы.

Если нужны данные из обеих таблиц, обычно удобнее `JOIN`. Если нужно только проверить наличие или отсутствие связанных строк, часто удобнее `EXISTS` или `NOT EXISTS`.

# LATERAL

`LATERAL` позволяет подзапросу в `FROM` обращаться к столбцам таблиц, указанных перед ним в том же `FROM`.

Например, получим для каждого пользователя его самый дорогой заказ:

```
SELECT u.name, o.amount
FROM users u
LEFT JOIN LATERAL (
    SELECT amount
    FROM orders
    WHERE user_id = u.id
    ORDER BY amount DESC
    LIMIT 1
) o ON TRUE;
```

Результат:

|name|amount|
|---|---|
|Олег|3000|
|Анна|500|
|Иван|NULL|

Подзапрос выбирает самый дорогой заказ конкретного пользователя. `LEFT JOIN LATERAL` позволяет сохранить пользователей без заказов.

# Основные конструкции: краткая шпаргалка

|Конструкция|Назначение|
|---|---|
|Скалярный подзапрос|Возвращает одно значение|
|Подзапрос в `FROM`|Создаёт временный набор строк|
|Подзапрос в `WHERE`|Фильтрует строки по результату другого запроса|
|Коррелированный подзапрос|Использует значения из внешнего запроса|
|`EXISTS`|Проверяет наличие строк|
|`NOT EXISTS`|Проверяет отсутствие строк|
|`IN`|Проверяет вхождение значения в набор|
|`NOT IN`|Проверяет невхождение значения в набор; требует внимания к `NULL`|
|`ANY` / `SOME`|Проверяет условие хотя бы для одного значения|
|`ALL`|Проверяет условие для каждого значения|
|`LATERAL`|Позволяет подзапросу в `FROM` ссылаться на предыдущие источники строк|

**Что особенно важно знать для собеседования:** разницу между `EXISTS` и `IN`, особенности `NOT IN` при `NULL`, разницу между `ANY` и `ALL`, а также отличие коррелированных подзапросов от обычных.
