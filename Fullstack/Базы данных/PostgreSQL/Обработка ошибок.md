В PostgreSQL оператор `RAISE` используется внутри **PL/pgSQL** для вывода сообщений, предупреждений и генерации ошибок. Обычно применяется в функциях, процедурах и триггерах.

### Уровни сообщений

|Уровень|Назначение|
|---|---|
|`DEBUG`|Отладочное сообщение|
|`LOG`|Запись сообщения в журнал сервера|
|`NOTICE`|Информационное сообщение|
|`WARNING`|Предупреждение, выполнение продолжается|
|`EXCEPTION`|Ошибка, выполнение текущей транзакции или блока прерывается|

Пример:

```
DO $$
BEGIN
    RAISE NOTICE 'Операция выполнена';
    RAISE WARNING 'Обнаружено предупреждение';
    RAISE EXCEPTION 'Произошла ошибка';
END;
$$;
```

После `RAISE EXCEPTION` выполнение блока прервётся, поэтому последующие инструкции не выполнятся.

### `RAISE EXCEPTION`

Позволяет самостоятельно генерировать ошибки, например при нарушении бизнес-правил.

```
DO $$
DECLARE
    balance NUMERIC := -100;
BEGIN
    IF balance < 0 THEN
        RAISE EXCEPTION 'Баланс не может быть отрицательным';
    END IF;
END;
$$;
```

По умолчанию `RAISE EXCEPTION` генерирует ошибку с SQLSTATE `P0001` (`raise_exception`).

### `RAISE USING`

Позволяет задать дополнительные параметры ошибки.

```
RAISE EXCEPTION USING
    MESSAGE = 'Баланс не может быть отрицательным',
    ERRCODE = '23514',
    HINT = 'Проверьте сумму операции';
```

Основные параметры:

- `MESSAGE` - текст ошибки.
- `ERRCODE` - код ошибки SQLSTATE.
- `DETAIL` - дополнительные подробности.
- `HINT` - рекомендация по исправлению ошибки.

Можно использовать и сокращённый синтаксис:

```
RAISE EXCEPTION 'Баланс: %, сумма списания: %',
    balance, amount;
```

Знак `%` заменяется соответствующим аргументом.

### Обработка ошибок: `EXCEPTION`

Блок `EXCEPTION` позволяет перехватывать ошибки и выполнять альтернативные действия.

```
DO $$
BEGIN
    INSERT INTO users (id, name)
    VALUES (1, 'Олег');

EXCEPTION
    WHEN unique_violation THEN
        RAISE NOTICE 'Пользователь с таким ID уже существует';

    WHEN OTHERS THEN
        RAISE NOTICE 'Произошла неизвестная ошибка';
END;
$$;
```

Здесь:

- `unique_violation` - нарушение уникальности, SQLSTATE `23505`.
- `OTHERS` - обработчик большинства остальных ошибок.

**Важно:** `WHEN OTHERS` не перехватывает абсолютно все ошибки. Например, он не обрабатывает `QUERY_CANCELED` и `ASSERT_FAILURE`.

Если ошибка перехвачена, выполнение продолжается после блока `EXCEPTION`.

### Повторный выброс ошибки: `RAISE;`

Если нужно перехватить ошибку, выполнить дополнительные действия и передать ошибку вызывающему коду, используется `RAISE;` без аргументов.

```
DO $$
BEGIN
    BEGIN
        INSERT INTO users (id, name)
        VALUES (1, 'Олег');

    EXCEPTION
        WHEN OTHERS THEN
            RAISE NOTICE 'Не удалось создать пользователя';
            RAISE;
    END;
END;
$$;
```

Сообщение будет выведено, а исходная ошибка продолжит распространяться.

### Пользовательские коды ошибок

Можно задавать собственные SQLSTATE:

```
RAISE EXCEPTION
    USING ERRCODE = 'P1001',
          MESSAGE = 'Недостаточно средств';
```

Пользовательские коды обычно выбирают из пяти символов, избегая кодов `00000` и заканчивающихся на `000`, поскольку последние обозначают категории ошибок.

### `ASSERT`

`ASSERT` используется для проверки условий, преимущественно при разработке и отладке.

```
ASSERT balance >= 0, 'Баланс не может быть отрицательным';
```

Если условие ложно, PostgreSQL генерирует ошибку `ASSERT_FAILURE`. Проверки `ASSERT` можно отключить настройкой `plpgsql.check_asserts`, поэтому использовать их для обязательной бизнес-валидации не следует.

---

### Что важно запомнить для собеседования

- `RAISE` - вывод сообщений и генерация ошибок.
- `RAISE EXCEPTION` - генерирует ошибку и прерывает выполнение текущего блока.
- `EXCEPTION WHEN` - перехватывает ошибки и позволяет обработать их.
- `RAISE;` - повторно выбрасывает текущую ошибку.
- `SQLSTATE` - пятисимвольный код состояния или ошибки.
- `ASSERT` - проверка условий для отладки, а не замена бизнес-валидации.

**Практический совет:** ограничения таблиц (`NOT NULL`, `CHECK`, `UNIQUE`, `FOREIGN KEY`) лучше использовать для обеспечения целостности данных, а `RAISE EXCEPTION` - для ошибок в процедурах и функциях, когда необходимо проверять бизнес-правила.
