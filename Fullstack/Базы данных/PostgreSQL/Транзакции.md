**Транзакция** - это группа SQL-операций, которая выполняется как единое целое: либо все изменения фиксируются, либо ни одно из них не сохраняется.

Транзакции нужны, чтобы поддерживать целостность данных при выполнении связанных операций.

## Основные команды

|Команда|Назначение|
|---|---|
|`BEGIN` / `START TRANSACTION`|Начинает транзакцию|
|`COMMIT`|Фиксирует изменения|
|`ROLLBACK`|Отменяет изменения текущей транзакции|
|`SAVEPOINT`|Создаёт точку сохранения|
|`ROLLBACK TO SAVEPOINT`|Откатывает изменения до точки сохранения|
|`RELEASE SAVEPOINT`|Удаляет точку сохранения|

### Пример транзакции

Переведём 100 рублей с одного банковского счёта на другой:

```
BEGIN;

UPDATE accounts
SET balance = balance - 100
WHERE id = 1;

UPDATE accounts
SET balance = balance + 100
WHERE id = 2;

COMMIT;
```

Если обе операции прошли успешно, изменения сохранятся.

Но если между операциями возникнет ошибка, можно выполнить:

```
ROLLBACK;
```

Обе операции будут отменены, если транзакция ещё не была зафиксирована.

**Важно:** `ROLLBACK` не отменяет изменения, которые уже были зафиксированы через `COMMIT`.

## ACID

ACID - четыре свойства, обеспечивающие надёжность транзакций.

|Свойство|Название|Описание|
|---|---|---|
|A|Atomicity (атомарность)|Все операции выполняются целиком или все отменяются|
|C|Consistency (согласованность)|Транзакция сохраняет целостность данных|
|I|Isolation (изоляция)|Параллельные транзакции не должны некорректно влиять друг на друга|
|D|Durability (долговечность)|После `COMMIT` изменения сохраняются даже при сбое системы в рамках гарантий СУБД|

## SAVEPOINT

`SAVEPOINT` позволяет откатить часть транзакции, не отменяя все предыдущие изменения.

```
BEGIN;

INSERT INTO users (name)
VALUES ('Олег');

SAVEPOINT user_created;

INSERT INTO orders (user_id, amount)
VALUES (1, 1000);

-- Отменяем изменения после точки сохранения
ROLLBACK TO SAVEPOINT user_created;

-- Сохраняем оставшиеся изменения
COMMIT;
```

В результате пользователь будет добавлен, а вставка заказа будет отменена.

`ROLLBACK TO SAVEPOINT` не завершает транзакцию - после него можно продолжить работу.

## Обработка ошибок внутри транзакций

В PostgreSQL ошибка внутри транзакции обычно переводит её в состояние aborted: дальнейшие SQL-команды не выполняются до отката.

Например:

```
BEGIN;

INSERT INTO users (id, name)
VALUES (1, 'Олег');

-- Допустим, id = 1 уже существует
INSERT INTO users (id, name)
VALUES (1, 'Иван');

-- Эта команда не выполнится
INSERT INTO users (id, name)
VALUES (2, 'Анна');

ROLLBACK;
```

После ошибки транзакция находится в состоянии, в котором обычные SQL-команды выполнять нельзя. Поэтому в конце используется `ROLLBACK`.

Чтобы продолжить транзакцию после ошибки, можно использовать `SAVEPOINT`:

```
BEGIN;

INSERT INTO users (id, name)
VALUES (1, 'Олег');

SAVEPOINT before_insert;

-- Допустим, возникнет ошибка уникальности
INSERT INTO users (id, name)
VALUES (1, 'Иван');

-- В обычном SQL этот ROLLBACK не выполнится автоматически:
-- его нужно отправить отдельной командой после обнаружения ошибки.
```

После ошибки необходимо выполнить `ROLLBACK TO SAVEPOINT before_insert`, а затем продолжить транзакцию.

В PL/pgSQL для этого также используется блок `BEGIN ... EXCEPTION ... END`, который позволяет перехватывать ошибки и продолжать выполнение внешней транзакции.

## Уровни изоляции транзакций

Уровень изоляции определяет, какие эффекты параллельных транзакций могут наблюдать друг у друга.

|Уровень|Особенности|
|---|---|
|`READ UNCOMMITTED`|В PostgreSQL работает как `READ COMMITTED`|
|`READ COMMITTED`|Каждая команда видит данные, зафиксированные к началу этой команды|
|`REPEATABLE READ`|Транзакция видит согласованный снимок данных, созданный в начале первого запроса, требующего такого снимка|
|`SERIALIZABLE`|Самый строгий уровень: результат успешных транзакций должен быть эквивалентен последовательному выполнению|

В PostgreSQL по умолчанию используется `READ COMMITTED`.

Задать уровень изоляции можно так:

```
BEGIN TRANSACTION ISOLATION LEVEL SERIALIZABLE;

SELECT *
FROM accounts;

COMMIT;
```

При `SERIALIZABLE` PostgreSQL может завершить одну из транзакций ошибкой сериализации. В таком случае приложение должно быть готово повторить транзакцию целиком.

## Автоматическая фиксация (autocommit)

В PostgreSQL каждая отдельная команда вне явной транзакции обычно выполняется в собственной неявной транзакции.

Например:

```
INSERT INTO users (name)
VALUES ('Олег');
```

Если команда успешно завершилась, её изменения автоматически фиксируются.

Если нужно объединить несколько команд в одну транзакцию, используют `BEGIN` и `COMMIT`.

## Блокировки и параллельные транзакции

При одновременном изменении данных несколькими транзакциями PostgreSQL использует блокировки, чтобы предотвращать некоторые конфликты.

Например:

```
BEGIN;

SELECT *
FROM accounts
WHERE id = 1
FOR UPDATE;

UPDATE accounts
SET balance = balance - 100
WHERE id = 1;

COMMIT;
```

`FOR UPDATE` блокирует выбранную строку для конфликтующих операций изменения до завершения транзакции.

Это полезно, когда приложение сначала читает данные, проверяет условие, а затем изменяет их.

Например, при списании денег можно заблокировать счёт, проверить баланс и только после этого выполнить списание.

## Коротко для собеседования

- **Транзакция** - группа операций, выполняемых как единое целое.
- **ACID** - атомарность, согласованность, изоляция и долговечность.
- `BEGIN` - начать транзакцию.
- `COMMIT` - зафиксировать изменения.
- `ROLLBACK` - отменить незакоммиченные изменения.
- `SAVEPOINT` - точка, до которой можно частично откатить транзакцию.
- **Уровень изоляции** - определяет видимость изменений параллельных транзакций.
- **Autocommit** - автоматическая фиксация отдельной команды вне явной транзакции.
- **Блокировки** - механизм координации конкурирующих операций.
- **MVCC** - механизм многоверсионности, позволяющий транзакциям читать согласованные версии данных и уменьшать конфликты чтения с записью.
