`JOIN` — объединяет строки из двух таблиц на основе условия связи между ними.

Допустим, есть таблицы `users` и `orders`.

**Таблица `users`**

|id|name|
|---|---|
|1|Олег|
|2|Анна|
|3|Иван|

**Таблица `orders`**

|id|user_id|amount|
|---|---|---|
|101|1|1000|
|102|1|2000|
|103|2|500|
|104|4|3000|

### INNER JOIN

`INNER JOIN` возвращает только строки, для которых найдено совпадение в обеих таблицах.

```
SELECT users.name, orders.amount
FROM users
INNER JOIN orders ON users.id = orders.user_id;
```

Результат:

|name|amount|
|---|---|
|Олег|1000|
|Олег|2000|
|Анна|500|

Заказы с `user_id = 4` исключены, потому что пользователя с таким `id` в таблице `users` нет. Иван тоже не попал в результат, потому что у него нет заказов.

`JOIN` без указания типа по умолчанию означает `INNER JOIN`.

### LEFT JOIN

`LEFT JOIN` возвращает все строки из левой таблицы и совпадения из правой. Если совпадения нет, столбцы правой таблицы заполняются `NULL`.

```
SELECT users.name, orders.amount
FROM users
LEFT JOIN orders ON users.id = orders.user_id;
```

Результат:

|name|amount|
|---|---|
|Олег|1000|
|Олег|2000|
|Анна|500|
|Иван|NULL|

Иван присутствует в результате, хотя у него нет заказов.

### RIGHT JOIN

`RIGHT JOIN` возвращает все строки из правой таблицы и совпадения из левой. Если совпадения нет, столбцы левой таблицы заполняются `NULL`.

```
SELECT users.name, orders.amount
FROM users
RIGHT JOIN orders ON users.id = orders.user_id;
```

Результат:

|name|amount|
|---|---|
|Олег|1000|
|Олег|2000|
|Анна|500|
|NULL|3000|

Заказ на 3000 сохраняется, хотя соответствующего пользователя нет в `users`.

### SELF JOIN

`SELF JOIN` — соединение таблицы с самой собой. Используется, когда нужно сопоставить записи одной таблицы между собой.

Например, в таблице `employees` у каждого сотрудника может быть руководитель.

|id|name|manager_id|
|---|---|---|
|1|Олег|NULL|
|2|Анна|1|
|3|Иван|1|
|4|Мария|2|

Запрос:

```
SELECT
    e.name AS employee,
    m.name AS manager
FROM employees e
LEFT JOIN employees m ON e.manager_id = m.id;
```

Результат:

|employee|manager|
|---|---|
|Олег|NULL|
|Анна|Олег|
|Иван|Олег|
|Мария|Анна|

Здесь `e` и `m` — псевдонимы одной и той же таблицы: `e` обозначает сотрудника, а `m` — его руководителя.

### USING

`USING` — сокращённая запись условия соединения, когда обе таблицы имеют столбец с одинаковым именем.

Например, обе таблицы содержат столбец `user_id`.

```
SELECT user_id, name, amount
FROM users_orders
JOIN payments USING (user_id);
```

Это аналогично:

```
SELECT u.user_id, u.name, p.amount
FROM users_orders u
JOIN payments p ON u.user_id = p.user_id;
```

Главное отличие: `USING (user_id)` позволяет не дублировать общий столбец в результате соединения.

**Важно:** `USING` работает только тогда, когда указанные столбцы есть в обеих таблицах.

### NATURAL JOIN

`NATURAL JOIN` автоматически соединяет таблицы по всем столбцам, которые имеют одинаковые имена.

```
SELECT *
FROM users_orders
NATURAL JOIN payments;
```

Если в обеих таблицах есть столбцы `user_id` и `order_id`, соединение будет выполнено по обоим столбцам.

**Недостаток:** если структура таблиц изменится и появится дополнительный столбец с одинаковым именем, условие соединения тоже изменится. Поэтому в реальных проектах чаще используют `JOIN ... ON` или `JOIN ... USING`.

### CROSS JOIN

`CROSS JOIN` — создаёт декартово произведение двух таблиц: каждая строка первой таблицы объединяется с каждой строкой второй таблицы.

### Пример

Таблица `colors`:

|color|
|---|
|Красный|
|Синий|

Таблица `sizes`:

|size|
|---|
|S|
|M|
|L|

Запрос:

```
SELECT *
FROM colors
CROSS JOIN sizes;
```

Результат:

|color|size|
|---|---|
|Красный|S|
|Красный|M|
|Красный|L|
|Синий|S|
|Синий|M|
|Синий|L|

В первой таблице 2 строки, во второй — 3. Результат содержит **2 × 3 = 6 строк**.

### Когда используется

Например, чтобы получить все возможные комбинации цветов и размеров товара.

## Краткое сравнение

| Вид            | Что возвращает                                         |
| -------------- | ------------------------------------------------------ |
| `INNER JOIN`   | Только совпавшие строки обеих таблиц                   |
| `LEFT JOIN`    | Все строки левой таблицы и совпадения правой           |
| `RIGHT JOIN`   | Все строки правой таблицы и совпадения левой           |
| `SELF JOIN`    | Соединение таблицы с самой собой                       |
| `USING`        | Упрощённое условие соединения по одноимённым столбцам  |
| `NATURAL JOIN` | Автоматическое соединение по всем одноимённым столбцам |
| `CROSS JOIN`   | Все возможные комбинации строк                         |

**Для собеседования:** чаще всего нужно уверенно объяснять `INNER JOIN`, `LEFT JOIN` и `JOIN ... ON`. Остальные конструкции используются для более специфичных задач.
