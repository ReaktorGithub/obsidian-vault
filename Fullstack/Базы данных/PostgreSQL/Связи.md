## Один-к-одному (One-to-One)

Каждой записи первой таблицы соответствует не более одной записи второй таблицы.

**Реализация:** `FOREIGN KEY` + `UNIQUE`.

```
CREATE TABLE users (
    id SERIAL PRIMARY KEY
);

CREATE TABLE profiles (
    id SERIAL PRIMARY KEY,
    user_id INTEGER UNIQUE REFERENCES users(id)
);
```

`UNIQUE` гарантирует, что у одного пользователя не будет нескольких профилей.

## Один-ко-многим (One-to-Many)

Одной записи первой таблицы соответствует несколько записей второй.

**Реализация:** `FOREIGN KEY` во второй таблице.

```
CREATE TABLE users (
    id SERIAL PRIMARY KEY
);

CREATE TABLE orders (
    id SERIAL PRIMARY KEY,
    user_id INTEGER REFERENCES users(id)
);
```

У одного пользователя может быть много заказов, но каждый заказ ссылается на одного пользователя.

## Многие-ко-многим (Many-to-Many)

Несколько записей первой таблицы связаны с несколькими записями второй.

**Реализация:** промежуточная таблица с двумя внешними ключами.

```
CREATE TABLE students (
    id SERIAL PRIMARY KEY
);

CREATE TABLE courses (
    id SERIAL PRIMARY KEY
);

CREATE TABLE student_courses (
    student_id INTEGER REFERENCES students(id),
    course_id INTEGER REFERENCES courses(id),
    PRIMARY KEY (student_id, course_id)
);
```

Студент может посещать несколько курсов, а каждый курс может посещать несколько студентов.

Составной `PRIMARY KEY (student_id, course_id)` не позволяет добавить одну и ту же пару студента и курса несколько раз.

| Тип связи        | Реализация                                  |
| ---------------- | ------------------------------------------- |
| Один-к-одному    | `FOREIGN KEY` + `UNIQUE`                    |
| Один-ко-многим   | `FOREIGN KEY` на стороне «многие»           |
| Многие-ко-многим | Промежуточная таблица с двумя `FOREIGN KEY` |
|                  |                                             |
