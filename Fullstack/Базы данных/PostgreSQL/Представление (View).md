**VIEW (представление)** - это виртуальная таблица, которая формируется на основе SQL-запроса. Обычно данные в ней физически не хранятся, а извлекаются из исходных таблиц при обращении к представлению.

### Создание представления

Допустим, есть таблица `employees`:

|id|name|department|salary|
|---|---|---|---|
|1|Иван|IT|150000|
|2|Анна|HR|100000|
|3|Пётр|IT|180000|

Создадим представление, которое содержит только IT-сотрудников:

```
CREATE VIEW it_employees AS
SELECT id, name, salary
FROM employees
WHERE department = 'IT';
```

Теперь можно обращаться к представлению как к обычной таблице:

```
SELECT * FROM it_employees;
```

Результат:

|id|name|salary|
|---|---|---|
|1|Иван|150000|
|3|Пётр|180000|

### Основные операции

**Удаление представления:**

```
DROP VIEW it_employees;
```

**Изменение определения представления:**

```
CREATE OR REPLACE VIEW it_employees AS
SELECT id, name
FROM employees
WHERE department = 'IT';
```

**Просмотр определения представления:**

```
SELECT definition
FROM pg_views
WHERE viewname = 'it_employees';
```

### Зачем нужны представления?

- **Упрощение запросов:** можно спрятать сложные `JOIN`, подзапросы и вычисления за простым именем.
- **Безопасность:** можно предоставить пользователю доступ только к определённым столбцам или строкам, не открывая доступ к исходной таблице напрямую. Для этого необходимо правильно настроить права доступа.
- **Повторное использование:** один запрос можно использовать в разных частях приложения.
- **Абстракция:** можно скрыть часть структуры базы данных от пользователей.

### VIEW и MATERIALIZED VIEW

В PostgreSQL есть два похожих механизма.

|Характеристика|VIEW|MATERIALIZED VIEW|
|---|---|---|
|Хранение результата|Обычно не хранится физически|Хранится физически|
|Получение данных|Запрос выполняется при обращении|Используется сохранённый результат|
|Актуальность|Отражает актуальные данные исходных таблиц при выполнении запроса|Может содержать устаревшие данные|
|Обновление|Отдельное обновление обычно не требуется|Выполняется через `REFRESH MATERIALIZED VIEW`|
|Производительность|Зависит от исходного запроса|Может ускорить тяжёлые запросы|

Создание материализованного представления:

```
CREATE MATERIALIZED VIEW department_stats AS
SELECT department, AVG(salary) AS avg_salary
FROM employees
GROUP BY department;
```

Обновление данных в нём:

```
REFRESH MATERIALIZED VIEW department_stats;
```

### Можно ли изменять данные через VIEW?

Иногда да. Простые представления в PostgreSQL поддерживают операции `INSERT`, `UPDATE` и `DELETE`, которые передаются исходным таблицам.

Однако представления с `GROUP BY`, агрегатными функциями, `DISTINCT` и некоторыми другими конструкциями обычно нельзя изменять напрямую без дополнительных механизмов, например триггеров `INSTEAD OF`.

### Кратко для собеседования

**VIEW** - виртуальная таблица, основанная на SQL-запросе. Она упрощает сложные запросы, позволяет повторно использовать логику выборки и ограничивать доступ к данным. В отличие от `MATERIALIZED VIEW`, обычное представление не хранит результат запроса физически, а материализованное хранит и требует обновления для получения актуальных данных.
