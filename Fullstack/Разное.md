### Сиды

Сиды (seeds) - начальные данные, которые автоматически добавляются в базу данных. Это часто используют в NestJS вместе с Prisma ORM.

```
npx prisma db seed
```

### Зачем нужны сиды?

- Создать тестовых пользователей, товары или заказы.
    
- Подготовить базу для локальной разработки.
    
- Добавить справочные данные, например роли `ADMIN` и `USER`.
    
- Наполнить базу демонстрационными данными для проверки приложения.

### Миграция

Миграция в базе данных - это изменение её структуры: создание таблиц, добавление или удаление полей, изменение типов данных, создание индексов и связей между таблицами.

В NestJS + Prisma ORM миграции позволяют хранить изменения структуры базы в виде файлов и последовательно применять их к базе данных.

### Пример

Допустим, у тебя есть модель пользователя в `prisma/schema.prisma`:

model User {
  id    Int    @id @default(autoincrement())
  name  String
  email String
}

Позже ты решил добавить поле `age`. Изменяешь модель:

model User {
  id    Int    @id @default(autoincrement())
  name  String
  email String
  age   Int?
}

Теперь создаёшь миграцию:

npx prisma migrate dev --name add-user-age

Prisma создаст SQL-файл миграции, который может выглядеть так:

ALTER TABLE "User" ADD COLUMN "age" INTEGER;

После применения миграции в таблице появится новое поле `age`.

Кратко для собеседования: миграции позволяют версионировать изменения структуры БД и синхронно применять их на разных окружениях - локально, на тестовом сервере и в продакшене. В Prisma я описываю структуру в `schema.prisma`, создаю миграцию командой `prisma migrate dev` и применяю подготовленные миграции на продакшене через `prisma migrate deploy`.

### Swagger

Swagger-декораторы в NestJS нужны для описания REST API и генерации интерактивной документации. Я использую `@ApiTags()`, `@ApiOperation()`, `@ApiResponse()` для эндпоинтов и `@ApiProperty()` для DTO. При этом Swagger отвечает за документацию, а валидацию выполняет `class-validator` через `ValidationPipe`, авторизацию - Guards.
