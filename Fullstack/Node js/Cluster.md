**`cluster`** - встроенный модуль Node.js, который позволяет запускать несколько дочерних процессов (workers) для выполнения одного приложения. Это помогает распределять обработку запросов между несколькими процессами и эффективнее использовать многоядерные процессоры.

## 1. Зачем нужен cluster?

По умолчанию Node.js выполняет JavaScript в основном потоке одного процесса. Если сервер работает на одном процессе, он не использует несколько ядер CPU для параллельного выполнения JavaScript-кода.

`cluster` позволяет запустить несколько процессов Node.js, каждый со своим экземпляром V8 и Event Loop.

Например, на сервере с 4 логическими ядрами можно запустить 4 worker-процесса:

- **Primary process** - управляет созданием и завершением workers.
- **Worker processes** - запускают приложение и обрабатывают запросы.
- **Балансировка нагрузки** - запросы распределяются между workers, которые могут слушать один и тот же порт.

Важно: `cluster` не ускоряет выполнение отдельного запроса автоматически. Он позволяет обслуживать больше запросов параллельно и использовать несколько ядер процессора.

## 2. Как работает cluster?

Схема работы:

1. Запускается основной процесс (primary).
2. Primary создаёт несколько worker-процессов.
3. Каждый worker запускает HTTP-сервер на одном порту.
4. Входящие соединения распределяются между workers.
5. Если worker завершается, primary может создать новый.

Каждый worker - отдельный процесс со своей памятью. Обычные переменные между процессами не разделяются.

## 3. Пример использования cluster

Создадим сервер `server.js`:

```
const cluster = require('node:cluster');
const http = require('node:http');
const os = require('node:os');

const numCPUs = os.availableParallelism();

if (cluster.isPrimary) {
  console.log(`Primary process: ${process.pid}`);

  // Создаём worker-процессы
  for (let i = 0; i < numCPUs; i++) {
    cluster.fork();
  }

  // Отслеживаем завершение worker
  cluster.on('exit', (worker, code, signal) => {
    console.log(`Worker ${worker.process.pid} завершился`);

    // Перезапускаем worker
    cluster.fork();
  });
} else {
  // Каждый worker запускает HTTP-сервер
  http.createServer((req, res) => {
    res.writeHead(200, {
      'Content-Type': 'text/plain; charset=utf-8',
    });

    res.end(`Обработано процессом ${process.pid}`);
  }).listen(3000);

  console.log(`Worker запущен: ${process.pid}`);
}
```

Запуск:

```
node server.js
```

Если доступно 4 логических ядра, программа создаст 4 worker-процесса. Запросы к `http://localhost:3000` могут обрабатываться разными workers.

Например, ответы могут содержать разные PID:

```
Обработано процессом 1234
Обработано процессом 1235
Обработано процессом 1236
```

**Важно:** `os.availableParallelism()` показывает доступную параллельную мощность, но это не всегда означает, что оптимально запускать ровно столько workers. Количество процессов выбирают с учётом нагрузки и доступных ресурсов.

## 4. Основные методы и свойства cluster

|Метод или свойство|Назначение|
|---|---|
|`cluster.fork()`|Создаёт новый worker-процесс|
|`cluster.isPrimary`|Проверяет, является ли текущий процесс основным|
|`cluster.isWorker`|Проверяет, выполняется ли код в worker|
|`cluster.workers`|Содержит активные worker-процессы|
|`cluster.on('exit')`|Обрабатывает завершение worker|
|`worker.process.pid`|Получает PID worker-процесса|
|`worker.kill()`|Завершает worker-процесс|
|`worker.send()`|Отправляет сообщение worker-процессу|

В современных версиях Node.js используется `cluster.isPrimary`. В старом коде можно встретить `cluster.isMaster` - это устаревшее название.

## 5. Как обмениваться данными между процессами?

Поскольку workers работают в отдельных процессах, они не разделяют обычные JavaScript-переменные.

Для обмена сообщениями можно использовать `process.send()` и событие `message`.

Например, в worker:

```
process.send({ status: 'ready' });

process.on('message', (message) => {
  console.log('Сообщение от primary:', message);
});
```

В primary:

```
const worker = cluster.fork();

worker.on('message', (message) => {
  console.log('Сообщение от worker:', message);
});

worker.send({ action: 'start' });
```

Таким образом можно передавать сообщения и простые данные между процессами.

Однако если всем workers нужен общий счётчик, состояние сессий или кэш, обычно используют внешнее хранилище, например Redis или базу данных.

## 6. Что происходит при падении worker?

Primary может отслеживать событие `exit` и создавать новый процесс взамен завершившегося.

Но в production недостаточно безусловно перезапускать процесс после любого завершения: это может вызвать бесконечный цикл рестартов, если приложение сразу падает при запуске.

На практике добавляют:

- задержку перед перезапуском;
- ограничение числа рестартов;
- логирование ошибок;
- корректное завершение workers;
- проверку готовности процесса перед включением в обслуживание.

Также важно учитывать, что перезапуск worker не восстанавливает запросы, которые он обрабатывал в момент падения.

## 7. Cluster и Worker Threads - в чём разница?

|Cluster|Worker Threads|
|---|---|
|Создаёт отдельные процессы Node.js|Создаёт дополнительные потоки внутри одного процесса|
|Каждый процесс имеет собственную память|Потоки могут обмениваться данными через `SharedArrayBuffer`|
|Подходит для распределения HTTP-запросов между процессами|Подходит для CPU-интенсивных задач|
|Есть отдельные экземпляры V8 и Event Loop|Потоки имеют отдельные контексты выполнения JavaScript|
|Обмен сообщениями между процессами|Обмен сообщениями между потоками|

Например, `cluster` можно использовать для запуска нескольких экземпляров API-сервера, а `Worker Threads` - для обработки больших объёмов данных, сложных вычислений или других CPU-интенсивных операций.

## 8. Cluster и балансировка нагрузки

По умолчанию `cluster` может распределять соединения между workers. В Linux обычно применяется механизм распределения соединений через primary, хотя доступен и вариант, при котором workers самостоятельно принимают соединения с общего порта.

Распределение не гарантирует, что каждый worker получит ровно одинаковое количество запросов: длительность запросов и особенности соединений могут различаться.

В крупных приложениях балансировку также часто выполняют внешние инструменты, например Nginx или облачные балансировщики.

## 9. Когда использовать cluster?

`cluster` может быть полезен, когда:

- нужно запускать несколько экземпляров HTTP-сервера на одной машине;
- приложение должно использовать несколько ядер CPU;
- необходимо повысить пропускную способность API;
- требуется перезапускать отдельные worker-процессы независимо друг от друга.

Но `cluster` не заменяет горизонтальное масштабирование на несколько серверов и не решает автоматически проблемы общей памяти, сессий или согласованности данных.

### Коротко для собеседования

`cluster` - встроенный модуль Node.js для запуска нескольких процессов одного приложения. Primary-процесс создаёт и контролирует workers, а те независимо обрабатывают запросы, что позволяет использовать несколько ядер CPU. Поскольку у каждого worker своя память, общее состояние обычно хранят в Redis или базе данных.
