Playwright - инструмент для E2E и интеграционного тестирования веб-приложений. На собеседовании обычно спрашивают не столько API, сколько понимание принципов работы.

### Особенности Playwright

- Поддерживает **Chromium, Firefox и WebKit**.
- Умеет работать с несколькими вкладками, окнами, iframe.
- Есть **auto-waiting** - Playwright сам ждёт, пока элемент станет доступен для действия.
- Поддерживает **network mocking** и перехват запросов.
- Есть **изоляция тестов** через Browser Context.
- Можно запускать тесты параллельно.
- Есть скриншоты, видео, trace для поиска причин падения теста.
- Поддерживает TypeScript из коробки.
- Можно тестировать авторизацию и сохранять состояние сессии.

### Плюсы

**1. Надёжность тестов**  
Auto-waiting уменьшает количество `sleep` и ручных ожиданий.

**2. Кроссбраузерность**  
Можно проверять поведение в Chromium, Firefox и WebKit.

**3. Хорошая работа с async**  
API изначально построен вокруг `async/await`.

**4. Удобная диагностика**  
Trace Viewer показывает действия теста, DOM, network и состояние страницы в момент ошибки.

**5. Изоляция**  
Каждый тест может запускаться в отдельном Browser Context, поэтому тесты меньше влияют друг на друга.

### Минусы

- E2E-тесты медленнее unit и большинства интеграционных тестов.
- Тесты могут быть нестабильными при плохих локаторах и неправильной архитектуре.
- Нужно поддерживать тесты при изменении UI.
- Запуск большого количества браузеров требует ресурсов.
- Сложнее настроить и поддерживать полноценный E2E pipeline, чем unit-тесты.

### Что могут спросить на собеседовании

1. **Что такое Playwright и для чего он нужен?**  
    Для E2E и интеграционного тестирования веб-приложений.
2. **Чем Playwright отличается от Cypress?**  
    Playwright лучше работает с несколькими вкладками, браузерами, iframe и имеет полноценную поддержку Chromium, Firefox и WebKit. Архитектура работы с браузером тоже отличается.
3. **Что такое Browser Context?**  
    Изолированная сессия браузера со своими cookies, localStorage и sessionStorage. Удобна для независимого запуска тестов.
4. **Что такое auto-waiting?**  
    Playwright автоматически ждёт, пока элемент станет подходящим для действия, например видимым и доступным для клика.
5. **Как выбрать элемент?**  
    Предпочтительно использовать пользовательские локаторы: `getByRole`, `getByText`, `getByLabel`, `getByTestId`.
6. **Как мокать API?**  
    Через `page.route()`. Можно перехватить запрос и вернуть тестовые данные вместо реального ответа сервера.
7. **Как тестировать авторизацию?**  
    Можно один раз авторизоваться и сохранить `storageState`, после чего использовать это состояние в других тестах.
8. **Как запускать тесты параллельно?**  
    Playwright Test использует workers. Тесты распределяются между worker-процессами.
9. **Как разобраться, почему E2E-тест упал?**  
    Использовать trace, скриншоты, видео, логи и network-информацию.
10. **Как уменьшить flaky-тесты?**  
    Использовать устойчивые локаторы, не применять `waitForTimeout` без необходимости, правильно изолировать тесты и использовать встроенные ожидания Playwright.

**На Middle+ я бы особенно подготовил:** `Browser Context`, auto-waiting, локаторы, `storageState`, `page.route`, параллельный запуск, fixtures и разницу между E2E, integration и unit-тестами.
