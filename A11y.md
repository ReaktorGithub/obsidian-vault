**Accessibility (a11y)** - это возможность пользоваться сайтом людям с разными ограничениями и разными способами взаимодействия: клавиатурой, скринридером, без мыши и т.д.

### Основные инструменты

**Семантический HTML:**

```
<button>Отправить</button>
<nav>...</nav>
<main>...</main>
<form>...</form>
<label>Имя</label>
```

Лучше использовать `<button>`, а не:

```
<div onclick="...">Отправить</div>
```

**ARIA-атрибуты** - когда обычной семантики HTML недостаточно:

```
<button aria-label="Закрыть">×</button>

<input aria-describedby="email-hint">
<p id="email-hint">Введите рабочую почту</p>

<div role="alert">Ошибка отправки</div>
```

Основные:

- `aria-label` - название элемента для скринридера
- `aria-labelledby` - ссылка на элемент с названием
- `aria-describedby` - ссылка на дополнительное описание
- `aria-label` / `aria-labelledby` - имя элемента
- `aria-expanded` - открыт ли dropdown, accordion и т.д.
- `aria-hidden` - скрыть элемент от скринридера
- `aria-live` - сообщить скринридеру об изменении контента
- `role` - семантическая роль элемента

### Клавиатура

Интерактивные элементы должны работать без мыши:

```
Tab       → переход между элементами
Enter     → активация
Space     → активация кнопки
Esc       → закрытие модалки
```

Также важно правильно управлять `focus` и не делать:

```
*:focus {
  outline: none;
}
```

без замены визуального индикатора фокуса.

### Ещё важно

- `alt` у информативных изображений
- правильные `<label>` для `<input>`
- достаточный контраст текста
- понятные названия кнопок
- логичный порядок `Tab`
- корректные заголовки `<h1> → <h2> → <h3>`
- не использовать `div` вместо интерактивных HTML-элементов без необходимости

**Для собеседования:**

> Accessibility - это доступность интерфейса для людей с ограничениями и пользователей, которые взаимодействуют с сайтом не только мышью. Основные инструменты - семантический HTML, ARIA, корректная работа с клавиатурой и focus, `alt`, `label`, контраст и правильная структура страницы.
