# Вопросы с собеседования

## 1. Что такое React Fiber?

**Ответ:**

Fiber - внутренняя архитектура React для reconciliation и планирования обновлений. Она представляет элементы дерева в виде Fiber-узлов и позволяет разбивать render work на части, прерывать его, менять приоритеты и продолжать позже.

---

## 2. Зачем вообще понадобился Fiber?

**Ответ:**

Старый reconciliation был в основном синхронным и мог надолго блокировать главный поток. Fiber позволил React делать работу прерываемой и планируемой, поэтому тяжелые обновления можно обрабатывать более гибко и поддерживать отзывчивость интерфейса.

---

## 3. Что такое Fiber Node?

**Ответ:**

Это внутренняя структура React, которая описывает компонент или элемент и хранит его props, state, связи с другими Fiber, информацию об обновлениях, приоритетах и эффектах.

---

## 4. Чем Fiber отличается от Virtual DOM?

**Ответ:**

Virtual DOM - концепция представления UI в JavaScript. Fiber - внутренняя структура React, которая используется для reconciliation и планирования работы с этим UI.

---

## 5. Что такое Render Phase?

**Ответ:**

На Render Phase React вызывает компоненты, строит новую версию Fiber-дерева и определяет, какие изменения нужны. Эта фаза может быть прервана и перезапущена, поэтому в ней не должно быть побочных эффектов.

---

## 6. Что такое Commit Phase?

**Ответ:**

Это фаза, в которой React применяет подготовленные изменения. Например, обновляет DOM и выполняет commit-related эффекты. В отличие от render phase, commit должен выполняться атомарно.

---

## 7. Может ли React прервать render?

**Ответ:**

Да. Это одна из основных возможностей Fiber. React может приостановить низкоприоритетную работу, обработать более важное обновление и затем продолжить или выбросить незавершенную работу.

---

## 8. Может ли React прервать commit?

**Ответ:**

Нет, commit не является такой же прерываемой фазой. После того как React начал commit, изменения применяются согласованно.

---

## 9. Concurrent React означает многопоточность?

**Ответ:**

Нет. Это не означает выполнение JavaScript в нескольких потоках. Concurrent rendering позволяет React прерывать, возобновлять и приоритизировать работу в рамках одного JavaScript-потока.

---

## 10. Что такое `lane`?

**Ответ:**

Lane - внутренняя модель React для представления приоритета и группировки обновлений. Она позволяет React выбирать, какую работу обрабатывать сейчас, а какую можно отложить.

---

## 11. Что такое `startTransition`?

**Ответ:**

`startTransition` позволяет пометить обновление как менее приоритетное. Например, изменение input можно выполнить срочно, а тяжелое обновление списка результатов сделать transition-обновлением.

---

## 12. Что произойдет?

```
setState(1);
setState(2);
```

**Ответ:**

React поставит два update в очередь, а благодаря batching они могут быть обработаны в рамках одного render. При этом итоговое состояние будет `2`.

---

## 13. Что такое batching?

**Ответ:**

Batching - объединение нескольких state updates в одну обработку, чтобы уменьшить количество render и commit. В современных версиях React automatic batching работает в большем количестве асинхронных сценариев, чем раньше.

---

## 14. Что такое `alternate`?

**Ответ:**

`alternate` связывает две версии Fiber одного узла - current и work-in-progress. Благодаря этому React может строить новую версию дерева отдельно от текущего отображаемого дерева.

---

## 15. Что такое Work In Progress Fiber?

**Ответ:**

Это версия Fiber-дерева, над которой React сейчас выполняет работу. После успешного commit она становится текущей версией дерева.

---

## 16. Зачем React два Fiber-дерева?

**Ответ:**

Чтобы React мог строить новую версию дерева, не изменяя текущую отображаемую версию. Это позволяет безопасно прерывать render и продолжать работу с WIP-деревом.

---

## 17. Что такое bailout?

**Ответ:**

Это оптимизация, при которой React понимает, что определенную часть дерева не нужно повторно вычислять. Например, `React.memo` может позволить пропустить render компонента, если его props не изменились.

---

## 18. Как `key` связан с Fiber?

**Ответ:**

`key` помогает React сопоставлять элементы нового дерева с существующими Fiber. Благодаря этому React понимает, какой элемент нужно сохранить, обновить, удалить или создать заново.

---

## 19. Почему нельзя использовать index как key?

**Ответ:**

Проблема возникает, когда порядок элементов меняется. Один и тот же index может начать соответствовать другому элементу, из-за чего React может сопоставить Fiber с неправильным элементом и, например, сохранить его state не там, где ожидается.

---

## 20. Что происходит при `setState` внутри React?

**Ответ:**

Создается update, он добавляется в очередь и получает соответствующий lane. Затем React планирует работу, выполняет render phase, определяет изменения и после этого применяет их во время commit phase.

---

## 21. Может ли компонент отрендериться несколько раз до одного commit?

**Ответ:**

Да. В concurrent rendering React может начать render, прервать его и выполнить render заново. Поэтому нельзя полагаться на то, что render будет выполнен ровно один раз перед commit.

---

## 22. Почему нельзя делать side effects во время render?

**Ответ:**

Потому что render может быть повторен или прерван и его результат может вообще не попасть в DOM. Если выполнить побочный эффект во время render, он может выполниться несколько раз или в ситуации, когда соответствующий UI так и не будет закоммичен.

---

## 23. Где тогда выполнять side effects?

**Ответ:**

В зависимости от задачи - обычно в `useEffect` или `useLayoutEffect`. Эти механизмы предназначены для работы с побочными эффектами после формирования UI.

---

## 24. `useEffect` выполняется в Render Phase?

**Ответ:**

Нет. React регистрирует effect во время render, но его callback выполняется после commit.

---

## 25. `useLayoutEffect` чем отличается от `useEffect`?

**Ответ:**

`useLayoutEffect` выполняется синхронно после изменений DOM и до того, как браузер отрисует результат. Он нужен, например, когда нужно измерить DOM и сразу скорректировать layout. `useEffect` выполняется позже и обычно предпочтительнее для обычных side effects.

---

# Каверзные вопросы

### "Fiber делает React многопоточным?"

**Нет.** Fiber дает возможность прерывать и планировать работу, но сам по себе не создает отдельный поток.

### "Fiber - это Virtual DOM?"

**Нет.** Fiber - внутренняя структура и архитектура React для работы с деревом и планирования обновлений.

### "Fiber гарантирует, что тяжелая функция не заблокирует UI?"

**Нет.** Если ты синхронно выполняешь очень тяжелую JavaScript-функцию, она всё равно блокирует главный поток.

### "Render всегда выполняется один раз?"

**Нет.** Render может выполняться несколько раз. Особенно это важно при concurrent rendering и `StrictMode` в development.

### "Если render был выполнен, значит DOM уже изменился?"

**Нет.**

```
render
↓
подготовили изменения
↓
commit
↓
изменили DOM
```

### "Можно ли делать API-запрос прямо в render?"

**Нет.** Render должен быть максимально чистым. Запрос является side effect и должен выполняться через соответствующий механизм, например `useEffect`, обработчик события или библиотеку управления server state.

---

# Как связать Fiber с остальным React

Полезно держать в голове такую цепочку:

```
setState
   ↓
Update
   ↓
Lane / priority
   ↓
Scheduler
   ↓
Fiber
   ↓
Render Phase
   ↓
Reconciliation
   ↓
Work In Progress
   ↓
Commit Phase
   ↓
DOM
```

А вокруг этого находятся:

```
React.memo
   ↓
bailout

key
   ↓
reconciliation

startTransition
   ↓
низкоприоритетный update

Suspense
   ↓
concurrent rendering

useTransition
   ↓
работа с transition state
```

### Самая важная мысль

Не стоит учить Fiber как набор внутренних полей (`child`, `sibling`, `alternate`, `lanes` и т.д.). На собеседовании гораздо важнее понимать **зачем он появился**:

> **Fiber превратил reconciliation из большой непрерывной операции в управляемую работу, которую React может планировать, приостанавливать, возобновлять и выполнять с разными приоритетами.**

И именно из этой идеи логично вытекают **Concurrent Rendering, transitions, lanes, bailout и современный scheduling React**.
