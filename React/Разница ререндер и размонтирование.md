### Ререндер

**Ререндер** — компонент снова выполняется, но его DOM-элемент обычно остается тем же.

Например:

```
function App() {
  const [count, setCount] = useState(0)

  useEffect(() => {
    console.log('effect')

    return () => {
      console.log('cleanup')
    }
  }, [count])

  return <button onClick={() => setCount(count + 1)}>{count}</button>
}
```

При `count: 0 → 1` происходит:

1. React вызывает `App()` заново.
2. Сравнивает новый результат со старым.
3. Если `button` остается тем же элементом, он **не размонтируется**.
4. Так как `count` изменился, React сначала вызывает старый `cleanup`.
5. Затем запускает новый `effect`.

То есть при изменении зависимости:

```
render
↓
cleanup старого effect
↓
effect
```

Важно: **обычный ререндер сам по себе cleanup не вызывает**. Cleanup вызывается перед повторным запуском эффекта, если изменились его зависимости.

### Размонтирование

**Размонтирование** — React полностью убирает компонент из дерева.

Например:

```
function App() {
  const [visible, setVisible] = useState(true)

  return (
    <>
      <button onClick={() => setVisible(!visible)}>
        Toggle
      </button>

      {visible && <User />}
    </>
  )
}
```

Когда `visible` становится `false`:

```
User
↓
unmount
↓
cleanup useEffect
```

При размонтировании cleanup вызывается **всегда**, если у эффекта он есть.

```
useEffect(() => {
  const timer = setInterval(() => {
    console.log('tick')
  }, 1000)

  return () => {
    clearInterval(timer)
  }
}, [])
```

Здесь `[]` означает, что эффект не будет повторно запускаться из-за изменения зависимостей. Но при размонтировании:

```
mount → effect
...
unmount → cleanup
```

### Главное отличие

|Ситуация|Компонент вызывается заново|Cleanup|
|---|---|---|
|Ререндер без изменения deps|Да|Нет|
|Ререндер с изменением deps|Да|Да, перед новым effect|
|Размонтирование|Нет|Да, окончательно|

Можно запомнить так:

**Ререндер ≠ размонтирование.**

Ререндер — React **заново вычисляет компонент**.

Размонтирование — React **удаляет компонент из дерева**.

И ещё важный момент: если при ререндере ты меняешь `key` компонента, React может воспринять это уже как **старый компонент удалили + новый создали**:

```
<User key={userId} />
```

При `userId: 1 → 2`:

```
User#1 → cleanup → unmount
                  ↓
               User#2
                  ↓
                effect
```

Именно поэтому `key` может приводить не просто к ререндеру, а к полному сбросу состояния и жизненного цикла компонента.
