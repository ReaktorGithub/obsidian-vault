> **React Fiber** — это внутренняя архитектура React, которая отвечает за планирование и выполнение обновлений UI. Она появилась начиная с React 16 и заменила старый reconciliation-механизм.
> 
> Главная идея Fiber — **разбить работу по обновлению интерфейса на небольшие части и управлять их приоритетом**. React может понять, какие обновления более важные, например ввод пользователя или анимация, а какие можно выполнить позже.
> 
> Когда меняется `state` или `props`, React запускает **render phase**. В этот момент Fiber строит и сравнивает новое дерево с предыдущим, определяет, какие элементы нужно добавить, удалить или обновить. Результатом становится набор изменений, который нужно применить к DOM.
> 
> Затем происходит **commit phase**. Здесь React уже применяет изменения к DOM и запускает соответствующие эффекты, например `useLayoutEffect`, а после отрисовки браузером - `useEffect`.
> 
> Каждая вершина Fiber-дерева представляет собой объект с информацией о конкретном компоненте или DOM-элементе. В нём React хранит, например, `props`, `state`, связи с родителем, дочерними и соседними Fiber-узлами, а также информацию об обновлениях и приоритетах.
> 
> Благодаря Fiber React получил возможность **прерывать, продолжать и переупорядочивать работу**. Это стало основой concurrent features в React 18, например `useTransition`, `useDeferredValue` и `Suspense`.
> 
> Важно, что Fiber - это **не DOM и не Virtual DOM**. Virtual DOM можно рассматривать как концепцию представления UI в памяти, а Fiber - конкретная внутренняя структура и архитектура React, которая позволяет React этим деревом управлять и планировать обновления.

### Если совсем кратко

> Fiber - это архитектура React для reconciliation и планирования обновлений. React представляет компоненты в виде Fiber-дерева, в render phase вычисляет изменения, а в commit phase применяет их к DOM. Главное преимущество Fiber - возможность разбивать работу на части, учитывать приоритеты и поддерживать прерываемые обновления, что стало основой concurrent features React 18.
