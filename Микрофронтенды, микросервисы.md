**Микрофронтенды** — подход, при котором большой frontend делится на **независимые части**, которые могут разрабатываться, тестироваться и выкатываться отдельными командами.

### Монолит vs микрофронтенды

**Монолит:**

- единое приложение
- единый runtime
- обычно единый deployable unit
- изменения одной части могут требовать сборки и деплоя всего приложения

**Микрофронтенды:**

- приложение разделено на независимые части
- разные команды могут иметь **ownership** над своими частями
- части могут независимо собираться и выкатываться

Важно: **монолитность определяется не количеством репозиториев и команд, а прежде всего границами приложения и способом его сборки и деплоя.**

### Module Federation

Один из способов реализации микрофронтендов в Webpack.

Есть:

**Host** — основное приложение.

**Remote** — отдельное приложение, которое предоставляет свои модули.

Host

 ├── Catalog

 ├── Cart

 └── Remote → Orders

Remote может собираться и выкатываться независимо от Host.

### Shared dependencies

Общие зависимости можно не дублировать:

Host

 └── React

  

Remote

 └── React ← shared

Например, React, React DOM и другие библиотеки могут быть объявлены как `shared`.

Проблема — **совместимость версий зависимостей**.

### Основные плюсы

- независимый деплой
- независимая разработка командами
- изоляция доменов
- возможность постепенно развивать части приложения
- проще распределять ownership

### Основные минусы

- сложнее архитектура
- сложнее коммуникация между микрофронтендами
- проблемы с shared dependencies
- сложнее отладка
- нужно поддерживать контракты между частями
- возможное дублирование зависимостей

### Workspace

**Workspace** — способ организовать несколько пакетов или приложений в одном репозитории.

Например:

frontend/

├── apps/

│   ├── host/

│   ├── catalog/

│   └── orders/

└── packages/

    ├── ui/

    └── shared/

Используется через **pnpm workspaces, npm workspaces, Yarn workspaces**.

**Turborepo** — инструмент для управления такими monorepo: кеширование, параллельные задачи, зависимости между пакетами и ускорение CI.

В одном из проектов использовал Module Federation: Host подключал Remote-модули, а общие зависимости вроде React выносились в shared. Основные сложности - контракты между микрофронтендами, версии shared-зависимостей и отладка распределённого приложения.»
