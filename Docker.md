### Как ответить на собеседовании

> Настраивал Docker-окружение для frontend-проекта. Использовал Dockerfile с multi-stage build: на первом этапе устанавливались зависимости и собирался React, на втором готовый build запускался через Nginx. Для локальной разработки использовал Docker Compose и переменные окружения. Также настраивал `.dockerignore`, конфигурацию Nginx для SPA и подключение Docker-сборки к CI/CD.

**Docker** — это контейнеризация приложения.  
Основные сущности:  
`Dockerfile` — как собрать image;  
`image` — шаблон приложения;  
`container` — запущенный экземпляр image;  
`docker-compose` — локально поднять несколько сервисов вместе: frontend, backend, Postgres, Redis и т.д.

**Kubernetes** — система оркестрации контейнеров.  
Основные сущности Kubernetes:  
**Pod** — минимальная единица запуска, обычно контейнер приложения;  
**Deployment** — описывает нужное количество реплик и обновление приложения;  
**Реплика (replica)** — **один запущенный экземпляр приложения**.
**Service** — стабильная точка доступа к Pod’ам;  
**Ingress** — внешний HTTP/HTTPS-доступ;  
**ConfigMap / Secret** — конфигурация и секреты;  
**ReplicaSet** — поддерживает нужное количество Pod’ов.  

Для проекта с таким стеком я бы отдельно добавил:

- `.dockerignore`, чтобы не копировать `node_modules`, `.git`, `dist`;
- разные Docker-конфигурации для development и production;
- переменные окружения;
- nginx-конфигурацию для SPA, чтобы React Router корректно работал при прямом переходе на `/dashboard`;
- healthcheck;
- Docker Compose для локального запуска связанных сервисов;
- интеграцию сборки Docker-образа в CI/CD.

Например:

```
docker-compose
      │
      ├── frontend
      ├── backend
      └── другие сервисы
```
