CSS-in-JS — это подход, при котором стили описываются с помощью JavaScript или TypeScript прямо в коде приложения. Например, с помощью styled-components или Emotion. Он позволяет динамически менять стили в зависимости от props, темы или состояния компонента.

CSS Modules — это обычные CSS-файлы, в которых классы автоматически получают локальные имена, чтобы не конфликтовать с классами других компонентов.

Главное отличие: CSS-in-JS позволяет описывать стили через JavaScript и динамически управлять ими, а CSS Modules изолирует обычный CSS от глобальных стилей.

### Styled components

### Плюсы

1. Изоляция стилей. Библиотека генерирует уникальные классы, поэтому стили разных компонентов не конфликтуют.
    
2. Динамические стили. Можно менять внешний вид через props без ручного управления множеством классов.
    

```
const Button = styled.button<{ primary: boolean }>`
  background: ${({ primary }) => primary ? 'blue' : 'gray'};
`;
```

3. Темизация. Через `ThemeProvider` можно централизованно управлять цветами, отступами и другими дизайн-токенами.
    
4. Инкапсуляция. Стили находятся рядом с компонентом, что упрощает поддержку и повторное использование.
    
5. Переиспользование. Можно создавать базовые стили и расширять существующие компоненты.
    

### Минусы

1. Производительность. Runtime-версия библиотеки может добавлять затраты на вычисление и применение стилей, особенно при большом количестве динамических компонентов.
    
2. Размер бандла. Библиотека увеличивает клиентский JavaScript.
    
3. SSR. Необходима корректная интеграция с серверным рендерингом, чтобы стили присутствовали в HTML и не возникало проблем с гидратацией.
    
4. Отладка. Генерируемые классы и стили могут быть менее удобны для анализа, чем обычные CSS-классы.
    
5. Сопровождение. Сложные шаблонные строки с большим количеством условий могут превращаться в трудночитаемую логику.
    
6. Зависимость от экосистемы. Нужно учитывать совместимость библиотеки с React и используемым фреймворком. Например, в современных проектах на Next.js важно отдельно проверять поддержку Server Components.
    

Итог: styled-components удобен, когда нужны динамические стили и централизованная темизация. Если стили преимущественно статические и важны простота и минимальные runtime-расходы, CSS Modules могут оказаться практичнее.

### Styled System (для дизайн системы)

**Styled System** — это библиотека и подход для создания **дизайн-систем в React**, где стили компонента задаются через props, а значения берутся из единой темы.

Например:

```
<Box
  padding={3}
  color="primary"
  fontSize={2}
  display="flex"
/>
```

Значения `3`, `primary`, `2` могут ссылаться на **design tokens** из `theme`:

```
const theme = {
  colors: {
    primary: '#0070f3',
  },
  space: [0, 4, 8, 16, 32],
};
```

### Зачем нужен

- Единые цвета, отступы, размеры и шрифты.
- Компоненты получают стили через props.
- Удобно строить **Design System**.
- Меньше произвольных значений вроде `margin: 17px`.
- Можно централизованно менять дизайн.

### Styled System vs styled-components

Это **не одно и то же**.

- **styled-components** — CSS-in-JS библиотека для создания стилизованных компонентов.
- **Styled System** — система API и design tokens, позволяющая задавать стили через props и тему.

Они могут использоваться вместе.

**Для конспекта:**

> Styled System — подход к построению дизайн-системы, где стили компонентов задаются через props, а значения берутся из централизованной темы и design tokens.
