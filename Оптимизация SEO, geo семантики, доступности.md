Если говорить о React / Next.js, то улучшение перформанса страниц с точки зрения SEO, GEO, семантики и доступности - это не только ускорение загрузки. Важно, чтобы поисковые системы и AI-поисковики понимали содержимое страницы, пользователи могли легко взаимодействовать с интерфейсом, а контент корректно отображался даже без выполнения клиентского JavaScript.
#### 1. Производительность и SEO

Основные задачи - ускорить загрузку, уменьшить объём ресурсов и обеспечить корректную индексацию.

- SSR / SSG - использовать серверный рендеринг или статическую генерацию в Next.js, чтобы поисковик получал содержательный HTML.
    
- Core Web Vitals - оптимизировать LCP, INP и CLS: ускорять загрузку главного контента, снижать задержки взаимодействия и предотвращать скачки вёрстки.
    
- Изображения - применять `next/image`, современные форматы WebP/AVIF, адаптивные размеры и lazy loading для изображений ниже первого экрана.
    
- JavaScript - удалять неиспользуемый код, использовать code splitting, динамический импорт тяжёлых компонентов и избегать лишней гидратации.
    
- Метаданные - задавать уникальные `title`, `description`, canonical URL и корректные Open Graph-метатеги.
    
- Индексация - проверять `robots.txt`, sitemap.xml, HTTP-статусы, редиректы, canonical и отсутствие случайного `noindex`.
    
#### 2. GEO - оптимизация для AI-поисковиков

GEO (Generative Engine Optimization) - работа над тем, чтобы контент сайта было проще находить, понимать и использовать в ответах генеративных поисковых систем и AI-ассистентов.

- Ответы на конкретные вопросы - раскрывать тему полно и по существу, давать определения, объяснения, сравнения и практические примеры.
    
- Доступность контента - важная информация должна присутствовать в индексируемом текстовом содержимом, а не только на изображениях, в canvas или после сложных пользовательских действий.
    
- Достоверность - публиковать оригинальный, полезный контент, указывать авторство и подтверждать фактические утверждения источниками там, где это уместно.
    
- Структурированные данные - использовать Schema.org и JSON-LD, например `Product`, `Article`, `Organization`, если они соответствуют содержимому страницы.
    
- Внутренние ссылки - связывать тематически связанные страницы, чтобы поисковым системам было проще обнаруживать и понимать контент.
    

Важный нюанс: отдельной гарантированной техники попадания в ответы ИИ нет. Google указывает, что для его AI-функций остаются актуальными обычные SEO-практики, а специальная AI-разметка или `llms.txt` не обязательны.

#### 3. Семантика HTML

Семантическая разметка описывает назначение элементов страницы, а не только их внешний вид.

Правильно

```
<header>...</header>
<nav aria-label="Основная навигация">...</nav>
<main>
  <h1>Каталог товаров</h1>
  <section>
    <h2>Популярные товары</h2>
    <article>...</article>
  </section>
</main>
<footer>...</footer>
```

Нежелательно

```
<div class="header">...</div>
<div class="nav">...</div>
<div class="title">Каталог товаров</div>
<div class="content">...</div>
```

На практике стоит:

- Использовать `header`, `nav`, `main`, `footer`, `article`, `section` по назначению.
    
- Выстраивать заголовки в логичную иерархию: `h1`, `h2`, `h3`.
    
- Для навигации применять ссылки `<a>`, а для действий - кнопки `<button>`.
    
- Добавлять осмысленный `alt` изображениям, несущим информацию.
    
- Не использовать HTML-теги только ради визуального оформления.
    

Семантика помогает вспомогательным технологиям ориентироваться на странице и упрощает понимание её структуры поисковыми системами.

#### 4. Доступность (Accessibility, a11y)

Цель - сделать страницу удобной для пользователей клавиатуры, скринридеров и людей с различными ограничениями.

- Клавиатурная навигация - все интерактивные элементы должны быть доступны через Tab, Enter и Space, где это предусмотрено поведением элемента.
    
- Фокус - видимый `focus`-стиль, логичный порядок переходов и отсутствие ловушек фокуса.
    
- Формы - каждому полю нужен связанный `label`, ошибки должны быть понятными и доступны вспомогательным технологиям.
    
- Контрастность - проверять контраст текста и фона по WCAG; не передавать смысл только цветом.
    
- ARIA - применять `aria-label`, `aria-expanded`, `aria-live` и другие атрибуты там, где нативной HTML-семантики недостаточно.
    
- Изображения - информативным изображениям задавать текстовую альтернативу, декоративным - `alt=""`.
    
- Динамический интерфейс - сообщать скринридерам об изменении состояния, например об ошибке отправки формы или результате поиска.
    

Для React полезно проверять интерфейс с помощью axe DevTools, Lighthouse и ручного тестирования клавиатурой. Автоматические инструменты выявляют только часть проблем, поэтому они не заменяют ручную проверку.

#### 5. Чем проверять результат

|Инструмент|Что проверять|
|---|---|
|Lighthouse|Performance, SEO, Accessibility, Best Practices|
|Chrome DevTools|Время загрузки, запросы, JavaScript, Layout Shifts|
|PageSpeed Insights|Core Web Vitals и рекомендации по производительности|
|Google Search Console|Индексацию, ошибки страниц и поисковую видимость|
|axe DevTools|Проблемы доступности|
|Rich Results Test|Корректность поддерживаемой структурированной разметки|
#### Приоритетный план для реального проекта

1. Сначала устранить критичные проблемы скорости

Проверить LCP, INP, CLS, размер бандла, тяжёлые изображения и лишний JavaScript.

2. Проверить SEO и индексацию

Метаданные, SSR/SSG, canonical, sitemap, HTTP-статусы, доступность контента для поисковых роботов.

3. Улучшить семантику и доступность

Заголовки, HTML-структура, подписи полей, клавиатурная навигация, контраст и ARIA.

4. Улучшить понятность контента для AI-поиска

Полезные ответы на вопросы пользователей, качественные источники, внутренняя перелинковка и подходящая структурированная разметка.

Для собеседования на Senior Frontend важно подчеркнуть, что ты не просто запускаешь Lighthouse и исправляешь предупреждения, а находишь узкие места, определяешь приоритеты, вносишь изменения и измеряешь результат до и после оптимизации. При этом SEO, GEO, семантика и доступность - взаимосвязанные, но разные направления: улучшение одного показателя не гарантирует автоматического роста остальных.
