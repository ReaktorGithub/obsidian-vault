### Как использовал на проекте?

Webpack использовал для сборки React-приложения: настраивал entry и output, loaders для TypeScript и стилей, плагины, алиасы и переменные окружения. Для production использовали code splitting, tree shaking, минификацию и contenthash для кеширования. При необходимости разбирал bundle и оптимизировал загрузку тяжёлых зависимостей через dynamic import.

### 10 популярных вопросов по Webpack

1. **Что такое Webpack?**  
    Webpack - сборщик модулей. Он собирает JS, CSS, изображения и другие ресурсы в бандлы, которые браузер может загрузить и выполнить.
2. **Что такое entry и output?**  
    `entry` - точка входа в приложение. Webpack начинает анализ зависимостей с неё. `output` определяет, куда и под каким именем будут складываться собранные файлы.
3. **Что такое loader?**  
    Loader преобразует файлы перед сборкой. Например, `ts-loader` обрабатывает TypeScript, а `css-loader` позволяет импортировать CSS в JS.
4. **Чем loader отличается от plugin?**  
    Loader преобразует отдельные файлы, а plugin может вмешиваться в процесс сборки целиком. Например, `HtmlWebpackPlugin` генерирует HTML-файл.
5. **Что такое code splitting?**  
    Разделение одного большого бандла на несколько чанков. Например, через `import()` можно загрузить код страницы только тогда, когда пользователь её открыл.
6. **Что такое tree shaking?**  
    Удаление неиспользуемого кода из финального бандла. Особенно эффективно работает с ES-модулями благодаря статическому анализу `import` и `export`.
7. **Что такое webpack-dev-server?**  
    Локальный сервер для разработки. Он пересобирает приложение при изменениях и может обновлять страницу или модули без полной перезагрузки.
8. **Что такое HMR?**  
    Hot Module Replacement позволяет заменить изменённый модуль прямо во время работы приложения, не перезагружая всю страницу. Например, можно изменить CSS и сразу увидеть результат.
9. **Как уменьшить размер бандла Webpack?**  
    Использовать code splitting, tree shaking, минификацию, оптимизацию изображений и анализировать бандл через Bundle Analyzer. Также важно не тянуть тяжёлые библиотеки целиком, если нужна только часть функциональности.
10. **Что такое webpack mode?**  
    `development`, `production` и `none`. `production` включает оптимизации вроде минификации и tree shaking, а `development` настроен на удобную и быструю разработку.

### Webpack vs Vite

| Критерий            | Webpack                 | Vite                              |
| ------------------- | ----------------------- | --------------------------------- |
| Назначение          | Bundler                 | Dev-сервер + bundler              |
| Development         | Собирает bundle         | Использует ESM                    |
| Скорость старта     | Обычно медленнее        | Обычно быстрее                    |
| HMR                 | Есть                    | Очень быстрый                     |
| Production          | Собирает сам            | Выполняет production build        |
| Конфигурация        | Сложнее и гибче         | Проще                             |
| Экосистема          | Огромная                | Современная и активно развивается |
| Microfrontends      | Module Federation       | Есть альтернативные решения       |
| Кастомизация        | Очень высокая           | Высокая                           |
| Типичное применение | Legacy, сложные проекты | Новые проекты                     |
### Главное различие

**Webpack в dev-режиме обычно сначала анализирует и собирает зависимости приложения в bundle.** Поэтому при большом проекте старт и обновления могут занимать заметное время.

**Vite в dev-режиме не собирает всё приложение целиком.** Он использует нативный ESM браузера и по запросу отдаёт нужные модули. Поэтому сервер стартует практически сразу, а HMR работает быстрее.

Условно:

```
Webpack:
код → анализ зависимостей → bundle → браузер

Vite dev:
код → ESM-модули → браузер
```

А production:

```
Vite:
код → production build → оптимизированные chunks

Webpack:
код → webpack build → оптимизированные chunks
```

### Что сказать на собеседовании

> **Webpack — более универсальный и глубоко настраиваемый bundler с огромной экосистемой. Vite в development использует нативный ESM и не собирает всё приложение перед запуском, поэтому старт и HMR обычно значительно быстрее. Для production Vite выполняет полноценную сборку и оптимизацию. Webpack чаще встречается в legacy и сложных кастомных проектах, а Vite сейчас часто выбирают для новых React-приложений.**

### Важный нюанс для собеседования

Не стоит говорить **«Vite — это просто новый Webpack»**.

Правильнее:

**Vite — это инструмент сборки и dev-сервер, который в development и production использует разные механизмы.** Его ключевая особенность — быстрый dev-режим благодаря ESM, а production-сборка выполняется отдельным bundling-процессом.

Если тебя спросят **«почему Vite быстрее Webpack?»**, главный ответ: **не нужно каждый раз собирать весь dependency graph в единый bundle для разработки.**
