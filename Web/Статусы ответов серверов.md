### 1xx - информационные

- `100 Continue` - сервер получил начало запроса, можно продолжать.
- `101 Switching Protocols` - переключение протокола, например на WebSocket.

### 2xx - успешный запрос

- `200 OK` - запрос выполнен успешно.
- `201 Created` - ресурс создан, например после `POST`.
- `202 Accepted` - запрос принят, но обработка ещё не завершена.
- `204 No Content` - успешно, но тело ответа отсутствует.

### 3xx - перенаправление

- `301 Moved Permanently` - ресурс навсегда перемещён.
- `302 Found` - временное перенаправление.
- `304 Not Modified` - ресурс не изменился, можно использовать кэш.

### 4xx - ошибка на стороне клиента

- `400 Bad Request` - неправильный запрос.
- `401 Unauthorized` - нет корректной аутентификации.
- `403 Forbidden` - доступ запрещён.
- `404 Not Found` - ресурс не найден.
- `409 Conflict` - конфликт состояния, например пользователь уже существует.
- `422 Unprocessable Content` - запрос понятен, но данные не проходят валидацию.
- `429 Too Many Requests` - слишком много запросов, сработал rate limit.

### 5xx - ошибка сервера

- `500 Internal Server Error` - внутренняя ошибка сервера.
- `502 Bad Gateway` - сервер получил некорректный ответ от другого сервера.
- `503 Service Unavailable` - сервер временно недоступен.
- `504 Gateway Timeout` - сервер не дождался ответа от другого сервера.

### Что обычно нужно помнить frontend-разработчику

```
200 - OK
201 - создано
204 - успешно, без body

400 - неправильный запрос
401 - не авторизован
403 - нет доступа
404 - не найдено
409 - конфликт
422 - ошибка валидации
429 - слишком много запросов

500 - ошибка сервера
502 - ошибка gateway
503 - сервис недоступен
504 - timeout gateway
```

**Важный момент:** `401` и `403` часто путают.

- `401` → проблема с **аутентификацией**: кто ты?
- `403` → пользователь известен, но **прав нет**: что тебе разрешено?
