 HTTPS (HTTP Secure) - HTTP с шифрованием через SSL/TLS. Отличия: данные шифруются (защита от перехвата), аутентификация сервера (сертификат), целостность данных (защита от подмены). Handshake процесс: клиент запрашивает SSL сертификат, проверяет его, устанавливает зашифрованное соединение. Использует порт 443 вместо 80. Обязательно для PWA, Geolocation API, современных браузеров.

HTTPS обязателен для production - защищает пользователей и SEO.
## **Версии**

**HTTP/0.9** - самая первая версия, 1991 г. Только `GET`. В ответе передавалось только тело документа. Заголовков и статус-кодов не было.

**HTTP/1.0** - 1996 г. Появились:

- HTTP-заголовки
- статус-коды (`200`, `404`, `500` и т.д.)
- методы `POST`, `HEAD`
- разные типы контента
- каждый запрос обычно создавал новое TCP-соединение

**HTTP/1.1** - 1997 г. Долгое время основной стандарт. Главное:

- постоянное соединение `keep-alive`
- несколько запросов через одно TCP-соединение
- `Host`
- `PUT`, `DELETE`, `OPTIONS`, `PATCH`
- `Transfer-Encoding: chunked`
- кэширование
- `Cookie`

**Проблема HTTP/1.1:** запросы идут последовательно. Если первый запрос долго обрабатывается, следующие могут ждать его завершения. Это называется **Head-of-Line Blocking** на уровне HTTP.

**HTTP/2** - 2015 г. Основное отличие - **бинарный протокол и мультиплексирование**.

- несколько запросов и ответов одновременно через одно TCP-соединение
- запросы разбиваются на **frames**
- используется **streams**
- сжатие заголовков через **HPACK**
- сервер может отправлять ресурсы заранее через **Server Push** (позже был фактически удалён из браузеров)
- порядок HTTP-запросов больше не блокирует другие запросы

**HTTP/3** - современная версия. Главное отличие - вместо TCP используется **QUIC поверх UDP**.

- HTTP/3 → QUIC → UDP
- мультиплексирование потоков
- потеря пакета в одном stream не блокирует остальные
- TLS 1.3 встроен в QUIC
- быстрее устанавливается соединение
- лучше работает при смене сети, например Wi-Fi → мобильная сеть

### Главное для собеседования

**HTTP/1.1** → TCP + текст + keep-alive  
**HTTP/2** → TCP + бинарные frames + multiplexing + HPACK  
**HTTP/3** → UDP + QUIC + multiplexing + TLS 1.3

Запомнить можно так:

**1.1 — много запросов, но TCP**  
**2 — много потоков внутри одного TCP**  
**3 — много потоков внутри QUIC поверх UDP**
