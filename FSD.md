**FSD** - архитектурная методология организации frontend-кода, которая разделяет приложение на слои и слайсы по назначению. Помогает масштабировать проект, упрощает поддержку и снижает связанность модулей.

## 1. Слои (Layers)

Слои определяют уровень ответственности модулей. Стандартная структура сверху вниз:

- `app` - инициализация приложения, глобальные провайдеры, роутинг, стили.
    
- `pages` - страницы приложения, собираются из виджетов и других модулей.
    
- `widgets` - крупные самостоятельные блоки интерфейса, например Header, Sidebar, Dashboard.
    
- `features` - пользовательские действия и бизнес-сценарии: авторизация, добавление в корзину, фильтрация товаров.
    
- `entities` - бизнес-сущности: User, Product, Order.
    
- `shared` - переиспользуемый код без привязки к конкретной бизнес-логике: UI-kit, API-клиент, утилиты, конфигурация.
    

Правило импортов: модуль может импортировать код только из слоев, расположенных ниже него. Например, `pages` может использовать `features`, `entities` и `shared`, но `shared` не может импортировать `features`.

## 2. Слайсы (Slices)

Слайсы делят код внутри слоя по бизнес-смыслу или назначению.

Пример:

- `entities/user`
    
- `entities/product`
    
- `features/add-to-cart`
    
- `features/auth-by-email`
    
- `widgets/header`
    

Слайсы одного слоя не должны напрямую импортировать друг друга. Например, `features/add-to-cart` не должен импортировать внутренние модули `features/auth-by-email`.

Исключение - слой `shared`, который не содержит слайсов в классическом понимании FSD.

## 3. Сегменты (Segments)

Сегменты делят слайс по типу кода:

- `ui` - компоненты интерфейса.
    
- `api` - запросы к серверу.
    
- `model` - состояние, бизнес-логика, экшены, селекторы.
    
- `lib` - вспомогательные функции и локальные библиотеки.
    
- `config` - конфигурация.
    

Пример структуры:

```text
features/
  add-to-cart/
    ui/
      AddToCartButton.tsx
    model/
      useAddToCart.ts
    api/
      addToCart.ts
    index.ts
```

Необязательно создавать все сегменты в каждом слайсе. Структура зависит от реальных потребностей модуля.

## 4. Public API

**Public API** - публичная точка входа слайса, через которую другие модули используют его функциональность.

```ts
// features/add-to-cart/index.ts
export { AddToCartButton } from './ui/AddToCartButton';
```

Импорт снаружи:

```ts
import { AddToCartButton } from '@/features/add-to-cart';
```

Вместо прямого импорта внутренних файлов:

```ts
import { AddToCartButton } from '@/features/add-to-cart/ui/AddToCartButton';
```

Преимущества:

- Скрывает внутреннюю реализацию.
    
- Упрощает рефакторинг.
    
- Контролирует доступные экспорты модуля.
    

## 5. Пример структуры проекта

```text
src/
  app/
    providers/
    router/
    styles/

  pages/
    dashboard/
      ui/
    products/
      ui/

  widgets/
    header/
    sidebar/
    product-table/

  features/
    auth/
    filter-products/
    add-to-cart/

  entities/
    user/
    product/
    order/

  shared/
    api/
    ui/
    lib/
    config/
```

## 6. Как выбирать слой

- `shared/ui` - универсальная кнопка или модальное окно.
    
- `entities/product` - типы товара, отображение его данных, работа с моделью товара.
    
- `features/add-to-cart` - сценарий добавления товара в корзину.
    
- `widgets/product-table` - самостоятельный блок таблицы товаров с фильтрами и управлением.
    
- `pages/products` - сборка страницы каталога.
    
- `app/providers` - глобальные провайдеры приложения.
    

Ориентир: сущность описывает бизнес-объект, фича реализует действие пользователя, виджет объединяет функциональные части интерфейса, страница собирает экран.

## 7. Преимущества FSD

- Разделение ответственности между модулями.
    
- Предсказуемая структура большого проекта.
    
- Повторное использование кода.
    
- Упрощение командной разработки.
    
- Удобный рефакторинг и развитие функциональности.
    

## 8. Частые ошибки

- Импорт между слайсами одного слоя.
    
- Импорт внутренних файлов вместо Public API.
    
- Размещение всей бизнес-логики в `shared`.
    
- Создание лишних слоев и слайсов для небольшого кода.
    
- Смешивание разных бизнес-сценариев в одном модуле.
    
- Чрезмерно дробная структура, усложняющая навигацию.
    

**Главное:** Layers отвечают на вопрос «на каком уровне находится код?», Slices - «к какой функциональности он относится?», Segments - «какую роль выполняет код внутри модуля?».
