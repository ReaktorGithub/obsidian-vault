## 1. Что такое ИИ-агент

**Ии-агент (AI Agent)** - система на основе ИИ, которая получает цель, анализирует ситуацию, выбирает действия, использует инструменты и повторяет процесс, пока не достигнет результата или не решит, что дальнейшие действия не нужны.

Пример: агент в Cursor может изучить код React-приложения, найти причину медленной работы таблицы, изменить код, запустить тесты и исправить ошибки.

## 2. Из чего состоит агент

- **LLM (Large Language Model)** - анализирует запрос, выбирает действия и генерирует ответы.
    
- **Instruction (инструкция)** - определяет цель, поведение и ограничения агента.
    
- **Context (контекст)** - история диалога, состояние задачи, результаты предыдущих действий и необходимые файлы.
    
- **Tools (инструменты)** - позволяют взаимодействовать с файлами, терминалом, API и внешними сервисами.
    
- **Agent Loop** - цикл принятия решений и выполнения действий.
    
- **Memory (память)** - позволяет сохранять и повторно использовать информацию между шагами или сессиями.
    
- **Runtime / Harness (среда выполнения)** - управляет инструментами, контекстом, разрешениями и обработкой ошибок.
    

Не каждый агент имеет долгосрочную память или сложную архитектуру. Иногда достаточно LLM, нескольких инструментов и цикла выполнения.

## 3. Agent Loop

**Agent Loop** - повторяющийся цикл, в котором модель анализирует контекст, выбирает действие, получает результат и принимает следующее решение.

Основные этапы:

1. **Observe (наблюдение)** - получение запроса, состояния задачи и результатов предыдущих шагов.
    
2. **Think / Plan (анализ и планирование)** - определение следующего действия.
    
3. **Act (действие)** - вызов инструмента, выполнение команды или изменение файла.
    
4. **Evaluate (оценка результата)** - анализ результата, обработка ошибок и обновление контекста.
    
5. **Repeat (повторение)** - переход к следующему шагу или завершение задачи.
    

Пример для React-разработки:

1. Получить задачу исправить фильтрацию таблицы.
    
2. Найти компонент и изучить логику фильтров.
    
3. Обнаружить ошибку в зависимостях `useMemo`.
    
4. Исправить код.
    
5. Запустить тесты.
    
6. Если тесты падают, проанализировать ошибку и внести исправления.
    
7. Если проверки проходят, сообщить результат.
    

Цикл завершается при достижении цели, формировании финального ответа, превышении лимитов или возникновении ошибки, которую невозможно обработать.

## 4. Tools (инструменты)

**Инструменты** - функции, с помощью которых агент выполняет операции за пределами генерации текста.

Модель выбирает инструмент и формирует аргументы, а среда агента выполняет операцию и возвращает результат в контекст.

Основные инструменты:

- `Read` - чтение файлов.
    
- `Search` - поиск файлов и текста в проекте.
    
- `Edit` - изменение кода.
    
- `Terminal` - выполнение команд, например `npm test`.
    
- `Browser` - взаимодействие с веб-страницами.
    
- `API` - получение и изменение данных внешних сервисов.
    
- `MCP Tools` - инструменты, предоставляемые MCP-серверами.
    

Пример вызова инструмента:

1. Модель запрашивает чтение файла `src/features/chart/Chart.tsx`.
    
2. Среда проверяет доступ и выполняет операцию.
    
3. Содержимое файла возвращается в контекст.
    
4. Модель анализирует код и выбирает следующий шаг.
    

Инструменты бывают встроенными и подключаемыми через MCP.

## 5. Context (контекст агента)

**Контекст** - информация, на основании которой модель принимает очередное решение.

Может включать:

- Системную инструкцию и правила.
    
- Запрос пользователя и историю диалога.
    
- План задачи и текущий статус.
    
- Содержимое прочитанных файлов.
    
- Результаты поиска и выполнения команд.
    
- Описания доступных инструментов.
    
- Данные из памяти и внешних источников.
    

### Контекстное окно и память

- **Контекстное окно** - максимальный объём информации, который модель может учитывать при обработке запроса. Измеряется в токенах.
    
- **Память (Memory)** - механизм хранения и повторного использования информации между шагами или сессиями.
    

Например, агент может получать архитектурные соглашения проекта из файла `AGENTS.md`, даже если история предыдущего диалога ему недоступна.

### Проблема большого контекста

Большое количество файлов, логов и сообщений может привести к переполнению контекстного окна и увеличению расходов.

Для управления контекстом используются:

- Поиск только релевантных файлов.
    
- Суммаризация предыдущих шагов.
    
- Сохранение плана и состояния задачи отдельно.
    
- RAG и поиск по проекту.
    
- Сокращение истории с сохранением важных результатов.
    

## 6. Instructions / System Prompt

**Инструкция** - набор указаний, определяющих роль, поведение, цели и ограничения агента.

Пример:

```
Ты - senior frontend-разработчик.

- Используй TypeScript.
- Соблюдай архитектуру Feature-Sliced Design.
- Перед изменением изучи существующий код.
- Не устанавливай новые зависимости без необходимости.
- После изменений запускай подходящие тесты.
- Не изменяй файлы вне задачи.
```

Инструкция может задавать:

- Роль и специализацию.
    
- Архитектурные соглашения.
    
- Порядок выполнения задачи.
    
- Ограничения на использование инструментов.
    
- Требования к тестированию.
    
- Формат итогового отчёта.
    

**Главное различие:** инструкция определяет, как агент должен работать, а инструменты дают ему возможность действовать.

## 7. Agent Harness (агентская оболочка)

**Agent Harness** - инфраструктура вокруг модели, которая превращает её в работающего агента.

В состав могут входить:

- Управление Agent Loop.
    
- Реестр инструментов и их вызов.
    
- Чтение и изменение файлов.
    
- Выполнение команд в терминале.
    
- Сбор и обновление контекста.
    
- Проверка разрешений и подтверждение опасных операций.
    
- Обработка ошибок и повторные попытки.
    
- Контроль токенов, времени и других лимитов.
    
- Логирование, checkpoints и восстановление состояния.
    

Примеры агентских сред:

- **Cursor** - AI-редактор кода с агентными возможностями.
    
- **Claude Code** - агент для работы с кодовой базой и терминалом.
    
- **OpenAI Codex** - агентная среда для выполнения задач разработки.
    
- **Cline** - агентный инструмент для разработки в редакторе.
    
- **Aider** - инструмент для работы с кодом через LLM.
    

Разные среды реализуют эти механизмы по-разному.

## 8. Rules, Skills, Commands и Hooks

### Rules (правила)

Правила задают ограничения, соглашения и требования к работе агента.

Пример:

- Использовать React Hook Form для форм.
    
- Соблюдать архитектуру FSD.
    
- Не создавать глобальное состояние без необходимости.
    

Примеры расположения: `.cursor/rules/*.mdc`, `AGENTS.md`. Конкретные форматы зависят от инструмента.

### Skills (навыки)

Навыки - переиспользуемые инструкции и материалы для определённого типа задач.

Примеры:

- Code review.
    
- Создание React-компонентов.
    
- Анализ производительности.
    
- Подготовка pull request.
    

Skill может содержать файл `SKILL.md`, дополнительные справочные материалы и скрипты. Агент использует его, когда навык подходит к задаче и поддерживается платформой.

### Commands (команды)

Команды - явно вызываемые пользователем сценарии или инструкции для повторяемых задач.

Примеры:

- `/review` - проверить изменения.
    
- `/test` - запустить или подготовить тестирование.
    
- `/fix-issue` - выполнить сценарий исправления ошибки.
    

Команда может задавать последовательность действий и ожидаемый результат. В разных инструментах команды реализованы по-разному.

### Hooks (хуки)

Хуки - механизмы запуска обработчиков при определённых событиях жизненного цикла агента.

Примеры:

- Перед выполнением команды проверить её безопасность.
    
- После изменения файла запустить форматирование.
    
- После завершения задачи записать отчёт.
    

В отличие от Rules, Hooks обычно запускаются по событию, а не просто служат инструкцией для модели.

### Сравнение

|Механизм|Назначение|
|---|---|
|Rules|Определяют ограничения и соглашения|
|Skills|Содержат специализированные инструкции и материалы|
|Commands|Запускают сценарии по запросу пользователя|
|Hooks|Реагируют на события и запускают обработчики|

Пример для React:

- Rule: использовать React Hook Form для форм.
    
- Skill: инструкция по созданию доступных форм с валидацией и тестами.
    
- Command: `/create-form` запускает сценарий создания формы.
    
- Hook: после изменения файла запускает форматирование.
    

## 9. Другие механизмы агентских систем

### Subagents (субагенты)

Отдельные агенты, которым делегируют части задачи. У них могут быть собственные инструкции, инструменты и контекст.

Пример: один агент анализирует производительность, второй проверяет тесты, третий исследует архитектуру. Главный агент собирает результаты.

Преимущества:

- Разделение сложной задачи на части.
    
- Возможность параллельного исследования.
    
- Независимая проверка результатов.
    

Недостатки:

- Дополнительные затраты токенов.
    
- Необходимость координации.
    
- Возможные конфликты при изменении одних и тех же файлов.
    

### MCP (Model Context Protocol)

Открытый протокол стандартизированного взаимодействия ИИ-приложений с внешними инструментами и данными.

Примеры интеграций:

- GitHub и Jira.
    
- Базы данных.
    
- Корпоративная документация.
    
- Внешние API.
    

MCP расширяет возможности агента и не является разновидностью инструкции.

### Memory (память)

Механизм хранения и повторного использования информации о проекте, предпочтениях или предыдущих задачах.

Память может храниться в файлах, базе данных или внутреннем хранилище платформы.

### Plan / Todo List (план)

Список этапов задачи с отметками выполнения.

Пример:

1. Изучить код.
    
2. Найти причину ошибки.
    
3. Исправить реализацию.
    
4. Добавить тест.
    
5. Проверить сборку.
    

Помогает агенту отслеживать прогресс при выполнении длительных задач.

### Permissions / Policies (разрешения и политики)

Определяют, какие действия агент может выполнять автоматически, а какие требуют подтверждения.

Пример: чтение файлов и запуск тестов разрешены, удаление базы данных требует подтверждения.

### Checkpoints / Worktrees

- **Checkpoint** - сохранённое состояние, к которому можно вернуться.
    
- **Git Worktree** - отдельная рабочая директория, связанная с Git-репозиторием.
    

Полезны для экспериментов и параллельной работы над задачами.

### Дополнительные понятия

- **MCP Prompts** - шаблоны запросов, предоставляемые MCP-сервером.
    
- **Plugins / Extensions** - расширения приложения, добавляющие интеграции и возможности.
    
- **Workflows** - заранее определённые последовательности шагов с условиями и ветвлениями.
    
- **Guardrails** - ограничения и проверки безопасности и качества.
    
- **Observability / Tracing** - логи вызовов, ошибки, время выполнения и расход токенов.
    
- **Evals** - тесты для оценки качества работы агента на наборе задач.
    

Эти понятия не образуют единого стандарта. Конкретные платформы могут использовать другие названия и механизмы.

## 10. Пример настройки агента для React-проекта

Допустим, агент должен добавлять новые функции в проект на React, TypeScript и FSD.

|Компонент|Назначение|
|---|---|
|`AGENTS.md`|Общие правила, стек, команды запуска и архитектурные ограничения|
|`skills/react-feature/SKILL.md`|Инструкции по созданию feature, подключению API и тестированию|
|`/review`|Команда для проверки изменений|
|Hook после изменения файла|Автоматическое форматирование или проверка|
|MCP для GitHub и Jira|Получение задач, просмотр issues и работа с pull request|
|Subagent для code review|Независимая проверка изменений|

Примерный процесс:

1. Пользователь поручает реализовать фильтрацию рекламных кампаний.
    
2. Агент читает правила и изучает код.
    
3. Использует специализированный Skill, если он подходит к задаче.
    
4. Создаёт план и изменяет компоненты.
    
5. Запускает тесты и проверки.
    
6. Hook выполняет дополнительную проверку, если настроено соответствующее событие.
    
7. Subagent проводит независимое ревью.
    
8. Главный агент исправляет замечания и сообщает результат.
    

Это пример возможной архитектуры. Для небольших задач достаточно обычного цикла с несколькими инструментами.

## 11. Проверка знаний

### Что такое Agent Loop?

Повторяющийся цикл анализа, выполнения действий и обработки результатов до завершения задачи.

### Чем Skill отличается от Rule?

Rule задаёт ограничения и соглашения, а Skill содержит специализированные инструкции и материалы для решения определённого типа задач.

### Для чего нужны Hooks?

Для запуска обработчиков при определённых событиях, например проверки безопасности перед выполнением команды.

### Что такое MCP?

Протокол взаимодействия ИИ-приложений с внешними инструментами и источниками данных.

### Зачем нужны Subagents?

Для делегирования частей задачи отдельным агентам, которые могут работать независимо или параллельно.

## Краткое резюме

**AI-агент** - LLM, работающая в цикле принятия решений и выполнения действий.

**Agent Harness** управляет циклом, инструментами, контекстом, разрешениями и обработкой ошибок.

- Rules - правила и ограничения.
    
- Skills - специализированные инструкции и материалы.
    
- Commands - сценарии, запускаемые по запросу.
    
- Hooks - обработчики событий.
    
- MCP - протокол подключения внешних инструментов и данных.
    
- Subagents - агенты, которым делегируют части задачи.
    
- Memory - сохранение информации между шагами или сессиями.
    
- Plan - отслеживание этапов выполнения задачи.
    
- Guardrails - ограничения безопасности и качества.
    
- Evals - оценка качества работы агента.
