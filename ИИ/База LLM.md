### Токены

**Токены** - единицы текста, на которые ИИ разбивает входные данные и ответы. Токеном может быть слово, часть слова или символ. Количество токенов влияет на стоимость запроса и объём контекста модели.

### Векторы

Вектор (embedding) - это набор чисел, в который ИИ преобразует текст, изображение или другой объект, чтобы представить его смысл в математическом виде.

Например:

- «Кот спит на диване» → `[0.12, 0.85, -0.34, ...]`
    
- «Кошка отдыхает на софе» → `[0.14, 0.82, -0.30, ...]`
    

Векторы этих предложений будут близки друг к другу, потому что их смысл похож.

Для чего нужны embeddings:

- Семантический поиск - поиск по смыслу, а не только по совпадению слов.
    
- RAG - поиск релевантных документов для передачи контекста языковой модели.
    
- Кластеризация - группировка похожих текстов.
    
- Рекомендации - подбор похожих товаров или материалов.
    

Главная идея: embeddings превращают смысл объектов в числа, а математическое расстояние между векторами помогает оценить их сходство.

### Температура

Температура в ИИ - параметр, который регулирует случайность ответов модели.

- Низкая температура (например, 0.1) - ответы более предсказуемые и стабильные.
    
- Высокая температура (например, 1.0) - ответы более разнообразные и креативные, но потенциально менее точные.
    

Пример: при просьбе написать историю низкая температура даст более типичный сюжет, а высокая - более неожиданный.

Технически температура изменяет распределение вероятностей выбора следующего токена: чем она выше, тем более равномерным становится распределение.
### Seed

Seed в ИИ - начальное число, которое используется генератором случайных чисел.

- Одинаковый seed помогает получать воспроизводимые результаты при повторных запусках с одинаковыми настройками и входными данными.
    
- Разный seed может приводить к разным результатам.
    

Seed полезен для тестирования и сравнения ответов модели. Однако он не гарантирует полной идентичности результатов: это зависит от модели, API и вычислительной среды.

### Контекст

Контекст в ИИ - информация, доступная модели при генерации ответа: текущий запрос, предыдущие сообщения диалога, системные инструкции и переданные данные.

- Контекстное окно - максимальный объём информации, который модель может учитывать за один запрос, измеряемый в токенах.
    
- Большой контекст позволяет работать с длинными документами и историей диалога.
    
- Переполнение контекста может привести к тому, что часть информации не поместится в окно и не будет учтена моделью.

### Transformer

- Transformer - архитектура нейронных сетей, лежащая в основе большинства современных LLM. Обрабатывает последовательности токенов с помощью механизма attention, учитывая связи между словами в контексте.

- Attention (механизм внимания) - механизм, который позволяет модели определять, на какие другие токены нужно обратить больше внимания при обработке текущего токена. Например, в предложении «Кошка запрыгнула на стол, потому что она испугалась» attention помогает связать слово «она» со словом «кошка».

Связь: Transformer - это архитектура, а attention - один из её ключевых механизмов. Несколько слоёв attention и других операций помогают модели понимать контекст и предсказывать следующие токены.

### RAG

RAG (Retrieval-Augmented Generation) - подход, при котором ИИ сначала ищет релевантную информацию во внешних источниках, а затем использует её для формирования ответа.

Как работает RAG:

1. Индексация - документы разбиваются на фрагменты (chunks), преобразуются в embeddings и сохраняются в векторной базе данных.
    
2. Поиск - запрос пользователя преобразуется в вектор, по которому находятся наиболее подходящие фрагменты.
    
3. Формирование контекста - найденные фрагменты добавляются к запросу пользователя.
    
4. Генерация - LLM формирует ответ на основе запроса и найденной информации.
    

Пример: пользователь спрашивает внутреннего ИИ-помощника компании, как оформить отпуск. RAG находит соответствующий раздел корпоративной документации и передаёт его модели для ответа.

Преимущества:

- Использование актуальных и внутренних данных без переобучения модели.
    
- Снижение вероятности галлюцинаций за счёт предоставления источников.
    
- Возможность ссылаться на документы, из которых взята информация.
    

Недостатки:

- Если поиск найдёт нерелевантные фрагменты, ответ может быть неправильным.
    
- Качество зависит от разбиения документов, embeddings и алгоритма поиска.
    
- Увеличиваются задержка ответа и сложность системы.
    

Ключевые компоненты: LLM, embeddings-модель, векторная база данных, механизм поиска и подготовка контекста.

Важно: RAG не обучает модель новым знаниям, а предоставляет ей нужную информацию непосредственно во время запроса.
