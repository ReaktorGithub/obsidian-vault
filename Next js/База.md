Next.js — это React-фреймворк, где приложение может работать одновременно на сервере и клиенте. По умолчанию компоненты в App Router серверные, интерактивность выносится в Client Components через `'use client'`. Next.js отвечает за routing, rendering, data fetching, caching, API endpoints, middleware и оптимизацию приложения.

**Next.js** — React-фреймворк, который добавляет:

- SSR / SSG / ISR
- Server Components
- маршрутизацию
- API / Route Handlers
- middleware
- оптимизацию изображений и шрифтов
- code splitting
- кеширование и revalidation

Основа: **React + Node.js runtime / Edge runtime**.

---

## App Router

Современный Next.js использует `app/`.

```
app/
├── layout.tsx
├── page.tsx
├── loading.tsx
├── error.tsx
├── not-found.tsx
├── users/
│   └── page.tsx
└── api/
    └── users/
        └── route.ts
```

### Основные файлы

|Файл|Назначение|
|---|---|
|`page.tsx`|страница / route|
|`layout.tsx`|общий layout|
|`loading.tsx`|loading UI|
|`error.tsx`|Error Boundary|
|`not-found.tsx`|404|
|`route.ts`|HTTP endpoint|

## Server Components

По умолчанию компоненты в `app/` — **Server Components**.

```
export default async function Page() {
  const data = await fetch('/api/users');

  return <div>{/* ... */}</div>;
}
```

Выполняются на сервере.

Плюсы:

- меньше JS отправляется браузеру
- можно обращаться к серверным ресурсам
- удобно получать данные
- секреты остаются на сервере

---

## Client Components

Для интерактивности используется:

```
'use client';
```

```
'use client';

import { useState } from 'react';

export function Counter() {
  const [count, setCount] = useState(0);

  return <button onClick={() => setCount(count + 1)}>{count}</button>;
}
```

Нужны для:

- `useState`
- `useEffect`
- обработчиков событий
- browser API
- интерактивного UI

```
Server Component
      ↓
Client Component
      ↓
useState / useEffect / onClick
```

Server Component **может импортировать Client Component**, но Client Component не должен напрямую импортировать Server Component.

# Рендеринг

Next.js поддерживает несколько подходов.

### SSR

HTML генерируется на сервере при запросе.

```
Browser
   ↓
Request
   ↓
Server
   ↓
HTML
   ↓
Browser
```

### SSG

HTML генерируется заранее во время build.

```
build
 ↓
HTML
 ↓
request → готовый HTML
```

### ISR

Страница генерируется заранее, но может периодически обновляться.

```
fetch(url, {
  next: {
    revalidate: 60
  }
});
```

---

# Hydration

После получения HTML браузер загружает JS для Client Components.

```
Server
 ↓
HTML
 ↓
Browser
 ↓
JavaScript
 ↓
Hydration
 ↓
Интерактивный React
```

Server Components сами по себе не гидратируются.

# Data Fetching

В Server Components можно получать данные напрямую:

```
const response = await fetch('/api/users');
const users = await response.json();
```

Next.js расширяет `fetch` механизмами:

- cache
- revalidate
- deduplication
- invalidation

---

# Cache

В Next.js есть несколько уровней кеширования.

Упрощённо:

```
Request
  ↓
Data Cache
  ↓
Full Route Cache
  ↓
Router Cache
```

### Revalidation

```
fetch(url, {
  next: {
    revalidate: 60
  }
});
```

Данные могут обновляться раз в 60 секунд.

Принудительно обновить:

```
revalidatePath('/users');
```

или

```
revalidateTag('users');
```

# Routing

Структура папок определяет URL.

```
app/
├── page.tsx
├── users/
│   └── page.tsx
└── users/[id]/
    └── page.tsx
```

Получаем:

```
/              → page.tsx
/users         → users/page.tsx
/users/123     → users/[id]/page.tsx
```

### Dynamic Routes

```
/users/[id]
```

```
export default async function Page({
  params
}: {
  params: Promise<{ id: string }>
}) {
  const { id } = await params;
}
```

# Middleware

`middleware.ts` используется для обработки запроса **до маршрута**.

Например:

```
Request
  ↓
Middleware
  ↓
Auth check
  ↓
Route
```

Используется для:

- auth
- redirect
- rewrite
- headers
- проверки cookie

---

# Server Actions

Позволяют выполнять серверную функцию непосредственно из UI.

```
'use server';

export async function createUser(formData: FormData) {
  // server
}
```

Используются для:

- mutations
- forms
- изменения данных
- работы с БД на сервере

# Архитектура запроса

Упрощённая схема:

```
Browser
   │
   ↓
Next.js Server
   │
   ├── Middleware
   │
   ├── Routing
   │
   ├── Server Components
   │       ↓
   │    Data Fetching
   │       ↓
   │    DB / API
   │
   └── Client Components
           ↓
        JavaScript
           ↓
        Browser
```

---

# Что происходит при открытии страницы

```
1. Browser → HTTP request
2. Middleware
3. Routing
4. Server Components
5. Получение данных
6. Генерация RSC payload + HTML
7. HTML → Browser
8. JS Client Components → Browser
9. Hydration
10. Страница становится интерактивной
```

```
React
 └── UI library

Next.js
 ├── React
 ├── Routing
 ├── SSR / SSG / ISR
 ├── Server Components
 ├── Server Actions
 ├── API / Route Handlers
 ├── Middleware
 ├── Caching
 └── Build / optimization
```
