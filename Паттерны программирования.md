### 1. GoF-паттерны

Самая классическая группа.

**Порождающие:**

- Factory Method
- Abstract Factory
- Builder
- Prototype
- Singleton

**Структурные:**

- Adapter
- Decorator
- Facade
- Proxy
- Composite
- Bridge
- Flyweight

**Поведенческие:**

- Observer
- Strategy
- Command
- State
- Template Method
- Iterator
- Chain of Responsibility
- Mediator
- Memento
- Visitor
- Interpreter

Из них в frontend особенно часто можно встретить:

**Observer, Strategy, Factory, Adapter, Decorator, Facade, Proxy, Command, State.**

---

### 2. Архитектурные паттерны

Это уже паттерны организации **всего приложения**, а не отдельных классов.

- MVC
- MVP
- MVVM
- Layered Architecture
- Clean Architecture
- Hexagonal Architecture
- Event-Driven Architecture
- Microservices
- Monolith
- Modular Monolith
- Micro Frontends

Для React-разработчика особенно полезно понимать:

**Layered Architecture, Clean Architecture, Event-Driven Architecture, Micro Frontends, Modular Monolith.**

---

### 3. Frontend-паттерны

То, что непосредственно встречается в React и других UI-приложениях:

- Container / Presentational
- Compound Components
- Render Props
- Higher-Order Component
- Custom Hooks
- Provider
- Controlled / Uncontrolled Components
- State Machine
- Observer
- Pub/Sub
- Event Bus

Например:

const Button = ({ children, onClick }) => {

  return <button onClick={onClick}>{children}</button>

}

Или Compound Components:

<Select>

  <Select.Trigger />

  <Select.Options />

  <Select.Option />

</Select>

---

### 4. Паттерны управления состоянием

Особенно актуально для React:

- Flux
- Redux
- Observer
- Pub/Sub
- State Machine
- Command
- Event Sourcing

Например, Redux во многом опирается на идею **однонаправленного потока данных**:

Action

  ↓

Reducer

  ↓

State

  ↓

UI

---

### 5. Интеграционные паттерны

Когда разные части системы должны взаимодействовать:

- Adapter
- Facade
- Proxy
- Gateway
- Repository
- Service Layer
- Dependency Injection
- Event Bus
- Message Broker
- Pub/Sub

Например, **Repository** скрывает детали работы с источником данных:

interface UserRepository {

  getUser(id: string): Promise<User>

}

А конкретная реализация может работать с REST API, GraphQL или базой данных.

---

### 6. Паттерны взаимодействия с API

В frontend часто встречаются:

- API Gateway
- Backend for Frontend (BFF)
- Repository
- Service Layer
- DTO
- Adapter
- Retry
- Circuit Breaker
- Cache-Aside
- Optimistic Update

Например:

Component

    ↓

Service

    ↓

API

Компоненту не нужно знать детали HTTP-запроса.

### Что я бы учил frontend-разработчику

Если цель — **собеседования и реальная работа**, не стоит пытаться зубрить все паттерны.

Я бы поставил приоритет так:

**Обязательно:**

1. Observer
2. Strategy
3. Factory
4. Adapter
5. Decorator
6. Facade
7. Proxy
8. Singleton
9. State
10. Command
11. Dependency Injection
12. Repository
13. MVC
14. Layered Architecture
15. Clean Architecture
16. Event-Driven Architecture

**Для React:**

17. Custom Hooks
18. Compound Components
19. Provider
20. Render Props
21. HOC
22. Controlled / Uncontrolled Components
23. State Machine
24. Pub/Sub / Event Bus

При этом важно понимать не только **«как выглядит паттерн»**, а **какую проблему он решает и какой недостаток появляется после его применения**. Именно это обычно отличает реальное понимание паттернов от заучивания определений.
